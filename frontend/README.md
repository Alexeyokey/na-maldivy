# Интерфейс «О!дин запрос»

Стандартный запуск для проверки приложения — [корневой README](../README.md):
`docker compose up --build` → [localhost:8080](http://localhost:8080).
Маршрут пользователя и ожидаемые результаты — [руководство судьи](../docs/judge-guide.md).

Этот документ описывает разработку интерфейса. HTML/CSS/ES modules работают
без сборщика и установки npm-зависимостей. Нужен Node.js 22+.

## Локальная разработка

При отдельно запущенном backend на `http://127.0.0.1:8000`:

```bash
cd frontend
npm run dev
# http://localhost:5173
```

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AGENT_URL` | `http://127.0.0.1:8000` | Backend для same-origin proxy; в Docker — `http://agent:8000`. |
| `CHAT_MODE` | `api` | Основной серверный интерфейс; `demo` — отдельный старый локальный прототип. |
| `HOST` | `127.0.0.1` | Адрес прослушивания dev-сервера. |
| `PORT` | `5173` | Порт dev-сервера; стандартный Docker runtime слушает 8080. |

Настройка режима на сервере имеет приоритет над старой настройкой браузера.
В `api` бриф, варианты, котировки, корзина и результат оплаты принадлежат backend.
Локальный `engine.js` в этом пути не вызывается; сбой API показывается ошибкой.

## Пользовательский путь

1. Запрос поступает в потоковый `/api/chat`. Карточки строятся из серверных
   `options`, панель — из `brief` и авторитетного снимка сессии. Текст ответа
   не используется как источник цен или выбранного варианта.
2. Предложенные/взятые по умолчанию условия подписаны отдельно. **«Подходит для
   поиска»** подтверждает только предположения и не создаёт корзину. Изменение
   параметров отправляется в чат; старые карточки и окна выбранного варианта
   перестают быть активными до нового подбора.
3. В карточках раскрывается состав цены, два или три отеля сравниваются в
   таблице. Длинный ответ раскрывается целиком через **«Подробнее — весь ответ»**;
   существенные ограничения остаются видимыми. Сравнение дат и факты из
   синтетических отзывов приходят с сервера.
4. Выбор отеля и **«Подтверждаю состав»** отправляют сообщения в тот же чат и
   создают неоплаченную серверную корзину. Клиент не задаёт свою цену.
5. Форма использует вымышленные имена и даты рождения. Два отдельных согласия
   с имитацией оплаты и неоценёнными расходами изначально не отмечены.
   Банковская карта не запрашивается.
6. **«Проверить отказ оплаты»** отправляет `declined`, оплаченный заказ не
   создаётся. **«Оплатить в демо»** отправляет `approved`; успех показывается
   только после серверных `paid_demo` и `is_simulated=true`. При неоднозначной
   сетевой ошибке сохраняется идемпотентный ключ.
7. Ваучер и `.ics` скачиваются через приватный запрос с `X-Session-ID` и Blob.
   **«Мои поездки»** открывает демо-заказы этой вкладки.

У каждого плеча указан источник: сохранённая котировка Aviasales или явный
**«ДЕМО-МОК»**. Сумма относится к известным компонентам на всю группу. Обратный
трансфер, визы и другие обязательные расходы не оценены. Деньги не списываются,
билеты не выписываются, услуги не бронируются; наличие и цена покупки неизвестны.

Поездная выдача Москва ↔ Петербург показывает вокзалы, время, длительность и
класс места. Расписание и цены демонстрационные. Корзина оформления
железнодорожных билетов не реализована.

## Состояние и восстановление

Вкладка сохраняет в `sessionStorage` переписку, черновик, публичные DTO и ссылки
доступа к своим заказам. Имена и даты рождения путешественников туда не
записываются. Технические идентификаторы не выводятся в видимый текст.

При обрыве полученная часть ответа остаётся видимой; повтор использует тот же
идентификатор сообщения. Если ответ уже завершён на сервере, клиент запрашивает
состояние, не выполняя поиск/оформление повторно. Изменённая или устаревшая
сессия проверяется перед включением действий. Поздний ответ от прежнего диалога
не должен обновлять новый поиск.

Новая поездка сбрасывает активную сессию, корзину и выбор, сохраняя ссылки на
прежние демо-документы. Backend хранит незавершённые поисковые сессии в памяти:
после его перезапуска поиск начинается заново. Оплаченные демо-заказы читаются
из SQLite и доступны через историю исходной вкладки. Общего аккаунта и
междустройственной истории нет. [Протокол восстановления](../docs/chat-recovery.md).

## Файлы

| Файл | Ответственность |
|---|---|
| `dist/api-app.js` | Основной API-интерфейс: карточки, сравнение, модальные окна, оформление и документы. |
| `dist/api-model.js` | Состояние, восстановление SSE, проверка снимка сессии, серверные корзины и ссылки на заказы. |
| `dist/api.js` | Потоковый SSE-клиент и checkout-запросы; UTF-8 и CRLF обрабатываются потоково. |
| `dist/message-format.js` | Безопасное форматирование ограниченного Markdown; HTML из ответа не исполняется. |
| `dist/trip-presentation.js` | Представление дат, чисел, склонений, предположений, состава цены и поездов. |
| `server.mjs` | Статика и узкий same-origin proxy для здоровья, чата, сессии, checkout и документов. |
| `dist/app.js`, `dist/engine.js`, `dist/bookings.js` | Старый локальный прототип для явного `CHAT_MODE=demo`; отдельный от серверной логики. |
| `dist/trip-canvas.js` | Совместимый модуль серверного canvas; основной API-интерфейс использует `api-app.js`/`api-model.js`. |

Proxy допускает только известные маршруты и методы, ограничивает тело 64 КБ,
передаёт заголовки по allowlist и не отправляет серверное окружение в браузер.
Ресурсы локальные; внешние шрифты не запрашиваются. Иллюстрации не выдаются за
фотографии конкретных отелей.

## Проверки

```bash
cd frontend
npm run check
npm test
npm run test:integration
```

- `check` — синтаксис модулей.
- `test` — состояние и переходы поездки, безопасное форматирование, SSE,
  предположения, источники/цены, согласия, отказ/успех оплаты, идемпотентность,
  восстановление и доступ к документам; отдельно проверяется локальный прототип.
- `test:integration` — временные HTTP-серверы, proxy allowlist, потоковый ответ,
  приватные заголовки и скачивание без ключей и внешних сервисов.

Эти тесты проверяют код и HTTP-границы. Полный визуальный проход в браузере
проверяется отдельно; сами тесты не заменяют демо-видео или человеческую защиту.
