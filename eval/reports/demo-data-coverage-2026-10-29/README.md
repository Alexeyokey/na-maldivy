# Полнота демо-данных — 29.10.2026

Данных достаточно для полного демонстрационного подбора AYT/DXB/MLE из Москвы
и Петербурга. В Git 60 отелей, 136 вариантов трансферов, 1440 синтетических
отзывов, 60 профилей и 47 очищенных исторических ответов Aviasales. Для новых
дат рейсы, предложения отелей и поезда вычисляются детерминированно. Генерировать
большие таблицы на каждый день или добавлять вымышленные отели не потребовалось.
Остальные 45 направлений D5 остаются справочными, без полного пакета поездки.

## Что исправлено и сгенерировано

- У 12 `adults_only` отелей один семейный шаблон противоречил запрету детей.
  Исправлены 12 корпусов и заново построены 12 профилей; остальные 48 пар
  сохранены побайтово. По-прежнему 24 текста на отель, без реальных отзывов,
  вызовов модели или запросов поставщикам. Дети/питомцы в профиле согласованы
  с синтетическими правилами. `--check` проверяет буквальные UTF-8 байты,
  включая дрейф LF/CRLF; повторная генерация сохраняет неизменившиеся файлы.
- При поиске на месяц ограничения длительности/пересадок/времени вылета
  учитываются до выбора даты. Если обратное плечо или проживание не совместимы,
  проверяется следующий день; явная дата не меняется. Даты упорядочены по цене
  подходящего перелёта туда, минимум полной стоимости не обещается.
- Описание младенческих тарифов в маршрутной сети приведено к `infant-v2`:
  до двух лет — модельные 10% без отдельного места/багажа; с двух лет — место.
- Закрытый серверный образ теперь копирует актуальный публичный `data/` вместе
  с кодом; новые профили не должны оставаться только в локальной сборке.

[Изменения и SHA256 публичного дерева данных](data-changes.json): 247 файлов,
3 089 170 байт; изменены 25 файлов (12 корпусов, 12 профилей, описание тарифов).
Названия/ID/OSM-факты и исторические ответы Aviasales не менялись.

## Что реально проверено

[Полный аудит](coverage.json): **146/146** ожидаемых исходов без сети/ключей/LLM,
в том числе даты до августа 2027, Новый год, семьи, младенцы, близнецы, питомцы,
большая группа, 1 и 60 ночей, жёсткие фильтры, низкий бюджет и поезда.
Четыре исхода намеренно пустые: прямой LED→MLE, поздний вылет MOW→MLE в дату
с сохранённым утренним рейсом и два недостижимых бюджета. Пустая выдача не
подменяется искусственно подходящим предложением.

[Первичный пробный прогон](initial-probe.json) охватывал 138 сценариев и не
включал два затем обнаруженных месячных дефекта. Его scope — исследование,
не приёмочный протокол. Новые месячные регрессии включены в итоговые 146.

[Трансферы](transfers.json): **5040 запросов / 11424 DTO-котировки** для всех
60 отелей, разных взрослых/возрастов/питомцев, дня и 23:40. Это проверка
совместимости данных и схем, не подтверждение настоящей перевозки.

[Проверки кода](checks.json): lint и **1823 теста** (backend 1538, frontend 274,
gateway 11). Тяжёлый месячный запрос через настоящий HTTP/SSE с `request_id`
проходит за измеренные 1,74 с: 432 КБ из 4 МиБ, 2472 события из 10000,
успешное завершение, совпадение GET и повтор без изменения ответа.

[Docker-проход](docker-initial.json) и [после перезапуска](docker-restart.json):
все три направления, демонстрационная оплата, документы и сохранность заказов.
Это отдельный HTTP-прогон; браузерная и LLM-приёмка им не подменяются.

## Повторить проверку

```bash
uv run --project backend --locked --offline python scripts/check_demo_coverage.py \
  --data-dir data --output /tmp/demo-coverage.json
```

`make demo-data-check` также запускает аудит. Набор не меняется: единственный
создаваемый файл — явно заданный отчёт вне `data/`. Повреждённые данные,
противоречивые профили и отсутствие сценариев дают ошибку проверки.

## Границы

На Мальдивах нет трансфера с явным `pets=true`: сохранены `false`/`null`,
положительный pet-friendly пример есть в Анталье/Дубае. Разрешение авиакомпании
на питомца, реальное наличие, актуальная цена и право въезда не подтверждены.
Запросы с невозможными ограничениями могут законно вернуть пустой результат.
Сгенерированные сведения остаются подписанными демо-данными. Настоящий D7
LLM-extraction и настоящий API Яндекс Расписаний этим аудитом не выполнялись.
Публикация и сохранность прежних серверных заказов фиксируются отдельно.
Тег `submission` не создавался.
