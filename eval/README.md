# O2: запросы У2 для общего эвала

`cases/u2.yaml` содержит 10 запросов зоны данных: направления, климат/визы,
поезда, семейный/питомец, невозможный бюджет, отмена, местные даты, сдвиг и провокация.
Тексты намеренно включают «150к», «пж», «Питер мск». Follow-up u2-08 содержит
контекст: перед проверкой его нужно связать с фактически выбранным hotel_id.

Формат `id/text/checks/tags` — предложение из #11, не утверждённый O1 TripState.
R6 #32 должен сопоставить декларативные свойства с реальным ответом агента.
Этот PR проверяет структуру и отсутствие дублей, не вычисляет метрики R6
и не заявляет, что fake-чат понимает эти запросы. Для финального набора из 50
ещё нужны по 10 запросов остальных четырёх зон.

Правила интерпретации: `all` проверяется только после наличия результатов;
пустой список не должен давать ложный успех. Для невозможного бюджета ожидается
ноль вариантов и объяснение. Неизвестные цены/визовые условия/срок отмены
не заменяются нулём, безвизовым режимом или придуманным дедлайном.
`price_scope` — проверяемая семантика суммы, а не обязательное поле DTO D1.
Синтетические тарифы не считаются подтверждёнными предложениями поставщиков.

Подготовка D9 и отдельный протокол пяти сквозных прогонов — `docs/demo.md`.
