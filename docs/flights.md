# D2: авиапоиск и воспроизводимые рейсы

Задача [#8](https://github.com/ostrovok-hackathon-2026/na-maldivy/issues/8).
PR основан на `codex/D1-tool-contracts`:
[D1 #50](https://github.com/ostrovok-hackathon-2026/na-maldivy/pull/50)
ещё не влит в main. Порядок слияния — D1, затем сменить базу D2 на main.

## Состав и происхождение данных

`FlightTool` реализует D1 `FlightSearch → list[Flight]`.
`search_with_provenance()` дополнительно возвращает исходные котировки и
происхождение расчёта каждого предложения. Подключение к чату/реестру A2 остаётся
отдельным шагом; глобальный реестр по умолчанию использует D1-заглушки.

| Источник | Что подтверждено |
|---|---|
| `data/routes/network.json` | Шесть наблюдавшихся пар SVO/LED → AYT/DXB/MLE, семь ссылок на официальные страницы. Проверка источников датирована 26.10.2026; часть страниц SVO исторические. Это не расписание на произвольную дату. |
| Аэропорты | IATA, округлённые опорные координаты и IANA-зоны из D1. |
| Демо-рейсы | Даты/время, длительность, тарифы, обратные направления, багаж и pet fees синтетические. |
| `aviasales_prices.synthetic.json` | Ручная фикстура формы ответа, не запись провайдера. |
| Aviasales Data API | Реализован клиент кэша поисковых наблюдений. Реальный запрос с партнёрским токеном не выполнялся; места и бронирование не подтверждены. |

LED–MLE моделируется с пересадкой через DXB; `direct_only=true` исключает этот
вариант. MOW сопоставляется с SVO явно. DXB не подменяется аэропортом DWC.
Для демо сеть разворачивается и в обратную сторону; это не доказательство
наличия обратного рейса в конкретный день. Источники и ограничения — в
[data/routes/README.md](../data/routes/README.md).

## Синтетический режим

```python
from app.contracts.tools import FlightSearch, Travelers
from app.tools.flights import FlightTool

query = FlightSearch(
    origin="SVO", destination="DXB", departure_date="2026-11-18",
    travelers=Travelers(adults=2, children_ages=[5]),
)
result = await FlightTool(mode="synthetic", seed=42).search_with_provenance(query)
```

На маршрут создаются вылеты в 09:00 и 23:30 по местному времени. Seed, дата,
направление и вариант определяют цену и длительность через SHA256; порядок
вызовов и `PYTHONHASHSEED` не влияют на ответ. Все предложения сохраняют
`is_synthetic=true`. Возвращаемые DTO и provenance можно менять без порчи
следующего запроса.

`price_rub` — **за всю группу в одну сторону**. Дети занимают полное место;
1500 ₽ за питомца включены. `baggage_price_rub` — отдельные 2000 ₽ на человека.
Их не нужно повторно умножать на группу. `max_price_rub` фильтрует стоимость
перелёта без отдельного багажа. Июль, август и декабрь имеют demo-множитель 1.2.

Вылет задаётся в `ZoneInfo` аэропорта; длительность прибавляется в UTC, затем
результат переводится в местный пояс прилёта. Проверены полночь, Новый год, DST
и граница календаря. `is_overnight` следует D1: местная дата прилёта позже
местной даты вылета; это не универсальное определение ночного рейса.

## Режим провайдера и D4

Клиент обращается к
[Aviasales Data API](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API):
`GET https://api.travelpayouts.com/aviasales/v3/prices_for_dates`, точная дата,
`one_way=true`, `direct`, `currency=rub`, `market=ru`, сортировка и пагинация.
Токен передаётся только в `X-Access-Token`.

```python
from app.tools.http_cache import CachedHttpClient  # D4, PR #56

async with CachedHttpClient(mode="record", cache_dir="../data/cache/aviasales") as http:
    tool = FlightTool(mode="provider", http=http, token=partner_token)
    result = await tool.search_with_provenance(query)
```

D2 принимает структурный `FlightHttpClient` с `mode` и асинхронным `get()`;
`CachedHttpClient` из [D4 #56](https://github.com/ostrovok-hackathon-2026/na-maldivy/pull/56)
соответствует этому интерфейсу. Демо и базовые тесты не требуют наличия кода D4.
Для производственного record/replay используется D4, а не копия его реализации.

Ответы с `success != true`, неверной валютой, round-trip, timestamp без offset,
неверными числовыми полями и неполной пагинацией отклоняются. Котировки чужого
аэропорта/локальной даты и пересадочные при `direct_only` исключаются.
Пустой ответ остаётся пустым; ошибки не включают синтетический fallback.

Исходная цена — наблюдение на одно место из кэша поисков. Групповая стоимость
вычисляется умножением на число людей и synthetic pet fee; багаж также моделируется.
Длительность берётся из `duration_to` или помеченной demo-оценки маршрута.
Поэтому даже provider-backed DTO имеет `is_synthetic=true`: доступность группы
и коммерческие условия не проверены. Исходная котировка сохраняется в `quotes`
и provenance, отдельно от расчётного предложения.

Record/live без токена даёт `ProviderNotConfigured`. Replay существующей записи
D4 работает без токена; пропуск записи даёт `CacheMiss`, без обращения в сеть.
Реальных API-записей Aviasales в этом PR нет.

## Запуск и проверки

```bash
cd backend
uv sync --locked
cd ..
make d2-demo      # только D2, два взрослых и ребёнок пяти лет, без сети
make d2-check     # весь backend, Ruff, схемы/примеры D1, затем демо
make d2-test      # обязательные тесты D2 и автономного демо
```

```bash
cd backend
uv run --locked --offline python -m app.d2_cli --json --origin LED --destination MLE --seed 777
```

После установки зависимостей команды D2 используют `uv --offline`.
Пять одинаковых запусков CLI проверяются с запрещёнными HTTP-клиентами и
сетевыми соединениями. Основные provider-тесты используют `httpx.MockTransport`
и явно синтетические ответы. Отдельно проверяются локальные даты/пересадки,
пагинация, строгие поля, групповой бюджет, вызов через `run_tool` и seed
между процессами. Подключения D3/D5/D6/D7/D8 и сборки У2 здесь нет.

`test_flights_d4.py` явно пропускается, если D4 ещё отсутствует. Полную связку
можно проверить до слияния #56, используя уже полученную локальную Git-ветку:

```bash
git fetch origin  # отдельно, если ветки D4 ещё нет локально
make d2-d4-test
```

Команда загружает только `http_cache.py` D4 из
`origin/codex/D4-cache-currency-pr` во временную папку этого тестового процесса,
показывает SHA коммита и запускает обе проверки record→replay/CacheMiss.
Она не меняет checkout, не устанавливает пакеты и сама не обращается в сеть.
Тестовый ответ Aviasales остаётся синтетическим. После появления D4 в текущей
ветке можно запускать `python ../scripts/check_d2_d4.py` из `backend/` без `--d4-ref`.

При выделении PR прошли: `make d2-check` — 436 тестов, Ruff, схемы/примеры D1
и демо; обязательный `make d2-test` — 58 тестов; `make d2-d4-test` — обе проверки
с кодом D4 из коммита `8a0445d`. В общем прогоне пропущен только модуль D4,
который затем проверен через эту временную загрузку. Конфигурация Compose проверена;
сборка образа и Docker smoke не подтверждены из-за недоступного Docker daemon.

## Оставшиеся шаги

Нужны партнёрский токен, проверка доступа/лимитов аккаунта, настоящая запись
ответа и оценка поведения API на нужных датах. Эти действия не подменяются
успешными mocks. Согласование O1 и подключение к A2 выполняются отдельно.
Сохранённые файлы доступны локально; Compose монтирует `./data` в `/data:ro`.
Образ сам по себе маршруты не содержит. Проверка Compose не подтверждает Docker smoke.
