# D1 v0.1: совместимость с S4, S3 и S5

Учтены [исходный ответ S4](https://github.com/ostrovok-hackathon-2026/na-maldivy/issues/2#issuecomment-6397086327)
и [ревью PR #50](https://github.com/ostrovok-hackathon-2026/na-maldivy/pull/50#issuecomment-6412625213).
Базовая версия готовит общую интеграцию; дальнейшие решения TripState и событий интерфейса остаются O1.

| Раньше | Теперь |
|---|---|
| LLM передаёт два полных `Place` с точными координатами | `TransferRequest(airport, hotel_id, pickup_at, travelers)`; точки находит сервер |
| Запрос в UTC или по Москве отклоняется | Внутренний `TransferQuery` нормализует aware-время в пояс отправления; выходной `Transfer` остаётся строгим |
| `get_transfer -> Transfer` | `list[Transfer]`: сначала по расписанию, затем без известных запретов, затем цена и ID |
| Нет составного вида трансфера | `flight_speedboat` — внутренний рейс с катером |
| Доступны только тариф и время в пути | Дополнительно `distance_km`, `luggage_limit`, `prebook_hours`, `issues` |
| В S4 свои Travelers и UnsupportedTransfer | Общие типы D1 и `app.tools.errors.UnsupportedTransfer(ValueError)` |
| Время заселения и выезда автоматически 14:00/12:00 | Неизвестные часы `null`; модельные отели задают их явно |
| Город отправления автоматически SVO | `DestinationQuery.origin` обязателен |
| LLM получает `$defs`/`$ref` | Локальные ссылки раскрываются без изменения ограничений |

## Подключение базы S4

```python
from app.tools.registry import run_tool, tool_specs
from app.tools.s4_adapter import S4TransferTool, transfer_leg

tools = {"get_transfer": S4TransferTool()}
quotes = await run_tool("get_transfer", {
    "airport": "MLE",
    "hotel_id": "osm:node/4455235191",
    "pickup_at": "2026-11-18T18:40:00Z",
    "travelers": {"adults": 2},
}, tools=tools)
leg = transfer_leg(quotes[0])
```

В Мале это запрос на 23:40; гидросамолёт отправится на следующий день в 06:00.
`S4TransferTool` читает каталог отелей и аэропортов на сервере; неизвестная или несовпадающая
пара аэропорт/отель вызывает общий `UnsupportedTransfer`. Ключи и сеть для опубликованной базы не нужны.
При `TRANSFERS_PATH` каталоги ищутся относительно того же корня данных; для отдельного набора
можно явно передать `base=` и `data_dir=`.

Адаптер сохраняет все варианты, цену за всю группу, расписание, число машин и рассчитанные S4 замечания.
`private_minivan` становится `minivan`, `speedboat` — `boat`, `flight_speedboat` сохраняется.
Составной трансфер не выдаётся за один катер: его суммарные время и цена относятся к обоим участкам.
`transfer_leg()` передаёт результат в S3/S5, сохраняя ID тарифа, цену и проблемы; длительность считается по UTC.
Модельные цены/часы/коммерческие правила остаются синтетическими, даже когда расстояние получено OSRM.

`available` относится к расписанию. Условия животных и кресел могут быть неизвестны: это не разрешение.
`issues` отражает конкретную группу, включая `pets_forbidden`/`pets_unknown` и замечания о кресле.
При сортировке запреты учитываются после расписания. Все варианты остаются в ответе для объяснений.
`hours=null` означает известную круглосуточную работу, а не отсутствие сведений.

## Совместимость отелей и таймлайна

`hotel_id` — постоянный физический объект, `offer_id` — конкретное предложение. У гостиничного `Place`
обязательны `kind="hotel"` и совпадающий ID. Канонический OSM-формат — `osm:way/123`; старое
`osm:way:123` нормализуется на входе. В JSON предложения выводится `offer_id`; `.id` оставлен для миграции.

S4 опубликован в main и содержит 60 отелей. В независимой ветке У2 — 72; совпадают 6 объектов.
Публичный адаптер поддерживает все 60 объектов S4, но не создаёт отсутствующие маршруты для других отелей.
Общий набор D3/S4 нужно выбрать при подключении поиска отелей.

Неизвестное время заселения/выезда сохраняется как `null`. S3 не придумывает события и ожидания,
а S5 выдаёт предупреждение `hotel_times_unknown` с исправлением `request_hotel_times` и неизвестной ценой.
Остальные проверки, включая запрет детей/животных и невозвратный тариф, продолжают работать.

## Проверка

- Все 17 вручную рассчитанных сценариев S4 проходят через публичный D1-инструмент.
- Для каждого из 60 отелей проверяются все его варианты (136 всего), ограничения и серверные координаты.
- Проверяются UTC/московское время с переходом местной даты, ночной гидросамолёт, группы с детьми/животными,
  JSON round-trip, общая ошибка неизвестного маршрута и передача участка в S3/S5.
- Схемы для LLM проверяются локально и через HTTP mock; проверка внешнего провайдера остаётся A3.

Генерируемые примеры: `contracts/examples/tools.json`, `contracts/examples/s4-transfers.json`.
Общий экспорт: `contracts/schema/tools.json`. Обновление: `make schemas tool-examples`; проверка: `make check-fast`.
