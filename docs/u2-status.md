# У2: выполненные независимые работы и границы интеграции

Срез: 26 октября 2026. Рабочая ветка `codex/U2-independent`, директория
`na-maldivy-U2`. В неё собраны прежние черновики D1/D5 и новые модули данных.
Исходные рабочие директории `na-maldivy` и `na-maldivy-D5` сохранены.
Общие контракты остаются версией 0 до O1. Issues не закрыты автоматически.

У2 не создаёт свой TripState, граф агента, ранжировщик R2, валидатор S5 или экраны.

## Как запустить и использовать

```bash
cd backend
uv sync --locked               # установка зависимостей; в первый раз может требовать сеть
cd ..
make u2-check                  # дальше без сети и платной модели
make u2-demo
cd backend
uv run --locked --offline python -m app.u2_cli --json
uv run --locked --offline python -m app.u2_cli --destination MLE
```

CLI демонстрирует данные и расчёты, не оформляет бронирования. Полный JSON
содержит источники, пометки синтетики, правила и профили. По умолчанию DXB,
15 ноября 2026, семь ночей, двое взрослых и ребёнок пяти лет.

Настраиваемая фабрика `app.tools.data_services.open_data_services(Settings(),
transport_mode="synthetic"|"provider")` предоставляет транспорт, отели и клиент
валют. Сеть определяется `CACHE_MODE`, по умолчанию `replay`. Кэш разделён по
провайдерам; разные аккаунты/тарифные контексты требуют разных `DATA_CACHE_DIR`.
`provider` без ключа в live/record сообщает ошибку; без записи в replay — `CacheMiss`.
Автоматического перехода на вымышленные ответы нет. Синтетический режим выбирается явно.

Богатые ответы `search_with_provenance` и `search_hotel_results` сохраняют
происхождение данных; D1 v0 не умеет выразить все эти сведения. Поэтому
`TOOLS_MODE=real` в старом общем реестре до адаптации остаётся явной ошибкой.
Скрытого подключения новых данных к агенту нет.

## Факты и синтетика

- География, OSM названия/координаты/заполненные звёзды, климат и ЦБ — сохранённые
  данные с источниками. Визовые записи — датированная справка с условиями;
  часть страниц КД МИД была доступна только через индекс официального сайта.
- Подтверждение маршрутной пары не доказывает выполнение рейса в выбранную дату.
  Все выбранные демо-даты, тарифы, групповые доплаты, правила и наличие вымышлены.
- Aviasales Data API — кэш цен поисков, не живое расписание или наличие билетов.
  Смешанный результат с ценой API всё равно помечается `is_synthetic=true`,
  поскольку расписание/группа/доплаты частично моделируются.
- Яндекс даёт расписание; цена и доступность класса — наша модель/неизвестность.
- OSM не даёт коммерческих правил. Синтетические отзывы, рейтинги, early check-in,
  возвратность, pet policy и 120-минутный трансфер ничего не утверждают о реальном отеле.
- Пример D8 считает перелёт с багажом и отель. Он не заменяет полную стоимость R2:
  трансферы, визы, страховки и другие необходимые расходы нужно добавить отдельно.
  Ночной прилёт в упрощённой сравнительной котировке исключается, чтобы не потерять ночь отеля.
- Лимит визы проверяется по известным датам/дням; null не означает бесконечность.
  Предыдущие поездки, остаток квоты, календарные окна и все требования допуска не вычисляются.

## Проверки и подготовка к передаче команде

`make u2-check` проверяет Ruff, все тесты бэкенда, воспроизводимость D5,
72 профиля, D1 Schema и автономный запуск. Отдельные проверки запрещают
сетевой транспорт, сравнивают пять запусков данных и разные Python hash seeds,
проверяют часовые пояса/DST, цены всей группы, жёсткие фильтры, цитаты,
границы визовых сроков и рублёвую экономию на границе 5%.

Итоговый запуск: **325 тестов прошли**, Ruff/форматирование, D5 rebuild-check,
72 profile-check, schema-check и CLI успешны. В проверке данных пять запусков
дали один результат при запрещённом HTTP-транспорте. `make check` и
`make check-fast` также принудительно используют replay и fake LLM.

Dockerfile включает готовые данные и явно задаёт `NA_MALDIVY_DATA_DIR=/app/data`;
кэш доступен на запись непривилегированному пользователю. Compose-конфигурация
проверяется отдельно. Сборка образа и Docker smoke требуют работающего Docker
daemon; в текущей среде его нет. Это ограничение проверки, а не подтверждённая сборка.

Следующие внешние шаги: согласовать O1 по существующему списку #2; локально
добавить ключи провайдеров и записать демо-запросы; подключить данные к A2/R2/R3/S3/S5;
затем выполнить пять настоящих сквозных прогонов D9. Точные инструкции и
источники находятся в `docs/tool-contracts.md`, `transport.md`, `hotels.md`,
`data-cache.md`, `destinations.md`, `price-calendar.md` и `demo.md`.
