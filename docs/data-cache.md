# D4: HTTP-кэш и курсы валют

Независимое ядро D4 работает без контрактов O1. Оно не вызывает LLM и не меняет интерфейс приложения.

## Запуск выделенного D4

```bash
cd backend
uv sync --locked
cd ..
make d4-demo    # сохранённый снимок ЦБ и конвертация 100 USD, принудительно replay
make d4-check   # Ruff, все тесты этой ветки, затем автономное демо D4
make d4-test    # отдельный набор кэша, валют и демо
```

После установки зависимостей команды D4 используют `uv --offline`.
Демо проверяет только кэш/валюты; чат, покупка и доступ к партнёрским API сюда не входят.

`Settings.cache_mode` читает `CACHE_MODE=record|replay|live`, по умолчанию `replay`.
`Settings.data_dir` / `DATA_DIR` задаёт единый корень данных; клиент ЦБ добавляет `cache/cbr`.
Пустое значение означает `data/` репозитория, независимо от текущей директории. Настройки используются
в `app.d4_cli`; реестр авиапоиска также передаёт их в `CachedHttpClient` при
`FLIGHTS_MODE=aviasales` (см. [подключение к чату](chat-aviasales.md)).

```bash
cd backend
CACHE_MODE=replay uv run --locked --offline python -m app.d4_cli --json --amount 100.50 --currency USD
```

`make check`, `make check-fast`, `make d4-check`, `make d4-test` и `make d4-demo`
выбирают replay, а проверки приложения используют fake LLM независимо от `.env`.
Для явного record/live запускайте CLI напрямую с нужным `CACHE_MODE`.
Record обновляет запись HTTP-кэша; исходный XML/provenance эталона автоматически не меняются.

Compose уже монтирует `./data` в `/data:ro`; по умолчанию `DATA_DIR=/data`.
Для record в контейнере нужна отдельная директория с правом записи и соответствующий mount.
Образ не содержит снимок сам по себе. Проверка конфигурации Compose не подтверждает сборку образа.

Историческая проверка при выделении PR `make d4-check`: Ruff, 200 тестов и автономное демо.
Два существующих теста совместимости S3/S5 с D1 пропущены через `importorskip`:
контракты PR #50 ещё отсутствуют в `main`; тесты D4 не пропускаются.
Отдельный `make d4-test` прошёл 113 тестов. Пять запусков D4 с запрещённым HTTP
дали одинаковый результат без изменения снимка. Проверена конфигурация Compose;
сборка образа и Docker smoke не проверены из-за отсутствующего Docker daemon.

## Режимы HTTP

`app.tools.http_cache.CachedHttpClient` возвращает обычный `httpx.Response`:

```python
from pathlib import Path
from app.tools.http_cache import CachedHttpClient

async with CachedHttpClient(mode="replay", cache_dir=Path("../data/cache/cbr")) as client:
    response = await client.get("https://www.cbr.ru/scripts/XML_daily.asp")
    response.raise_for_status()
```

| Режим | Поведение |
|---|---|
| `replay` — по умолчанию | Только чтение сохранённого ответа. Нет записи — `CacheMiss`, без сетевого обхода |
| `record` | Настоящий HTTP-запрос, безопасная обработка ответа, атомарное сохранение. Повторная запись заменяет запись |
| `live` | Настоящий HTTP-запрос и безопасная обработка, кэш не читается и не записывается |

Методы: `await get(url, params=..., headers=...)` и `await request(method, url, params=..., headers=...,
json=..., data=..., content=..., timeout=...)`. Есть `async with`, `aclose()` и асинхронный `close()`.

Переадресации автоматически не выполняются. Сетевые сбои превращаются в `ProviderRequestError`
без исходного URL/текста провайдера. HTTP-статусы сохраняются: вызывающий код сам использует
`raise_for_status()`. Даже ошибки провайдера можно воспроизводить; их секреты удаляются.

Инъекция `client=httpx.AsyncClient(transport=...)` нужна для тестов и управления транспортом.
Его настройки query/headers/auth не добавляются неявно: передавайте параметры и заголовки в вызов.
Внешний клиент обёртка не закрывает; собственный клиент закрывает. Файловые операции вынесены
в рабочий поток и не блокируют цикл async-сервиса.

## Ключ и сохранность данных

Ключ — SHA256 от метода, нормализованного публичного URL, влияющих на ответ заголовков и тела запроса.
Host приводится к нижнему регистру, стандартный порт и fragment удаляются, query-параметры сортируются
по имени; порядок повторных значений одного параметра сохраняется. Порядок ключей JSON не влияет
на ключ. Разные даты, города, состав группы, валюта и язык не объединяются в одну запись.

Из идентичности запроса удаляются известные имена секретов: API keys, access tokens, пароли,
Authorization, Cookie и подобные. Поэтому запись публичного ответа можно воспроизвести без ключа API.
Регистр, дефисы и подчёркивания имён учитываются. Транспортные заголовки не входят в ключ.

Секреты удаляются из query/userinfo URL, заголовков, вложенных JSON и form-тел, XML/текстовых
диагностик и отражённых сообщений ошибок. Cookie-атрибуты `Path`, `SameSite`, `Max-Age` не считаются
значениями секретов. `Set-Cookie` и авторизационные заголовки ответа на диск не попадают.
Для нестандартных полей передавайте `secret_values=[...]`: имена и неизвестные строки невозможно
безошибочно классифицировать универсальным правилом.

Это кэш **публичных обезличенных данных**. Для аккаунтов/тарифов/тенантов с разными ответами используйте
разные директории. Ключ намеренно не различает учётные данные; не сохраняйте сюда бронирования,
пассажирские документы или личные профили. Данные, отредактированные как секретные, не восстанавливаются
при replay. Для тел запросов поддержаны JSON/form, для ответов — декодируемый текст/JSON/XML.
Неопознаваемое бинарное содержимое и невалидный JSON отклоняются с `CacheSafetyError`.

Запись содержит версию формата, безопасный запрос, дату записи UTC, статус/заголовки и тело Base64
с SHA256. Base64 сохраняет исходную кодировку XML; это не шифрование. Запись делается во временный
файл с последующим `fsync` и `os.replace`: незавершённый ответ не заменяет предыдущую запись.
Повреждённая запись даёт `CacheFormatError`; сетевого fallback нет. Автоматического TTL нет:
для записи известен `recorded_at`, политику обновления выбирает адаптер.
В `record` и `replay` клиент возвращает это значение также в
`response.extensions["recorded_at"]`. D2 переносит его в публичный `Flight.price_source`,
не раскрывая содержимое запроса или авторизацию.

## Курсы Банка России

Первичные источники:

- [XML API Банка России](https://www.cbr.ru/development/SXML/): `date_req=дд/мм/гггг`;
  без параметра — последняя зарегистрированная дата.
- [Документация сервиса ЦБ](https://www.cbr.ru/development/DWS/): поля номинала и курса.

`app.tools.currency.load_cbr_rates(client, date=None)` использует тот же клиент и его режим.
При отсутствии записи он не подменяет replay прямым запросом. `CurrencyRates.from_xml(...)`
позволяет проверить уже полученный XML. Некорректный документ, DTD/entities, нулевой номинал,
повторная валюта и неправильные даты отклоняются безопасной ошибкой.

```python
from datetime import date
from app.tools.currency import load_cbr_rates
from app.tools.http_cache import CachedHttpClient

async with CachedHttpClient(cache_dir="../data/cache/cbr") as client:
    rates = await load_cbr_rates(client)
    price = rates.convert("100.50", "USD")  # строка или Decimal, не float
    print(price.amount_rub, rates.effective_date)
    print(rates.is_stale(as_of=date(2026, 10, 26), max_age_days=3))
```

`Value` — стоимость **Nominal** единиц валюты в рублях. Расчёт на одну единицу:
`value_rub / nominal`; номинал 10/100/1000 не теряется. Все операции через `Decimal`, округление
до целого рубля `ROUND_HALF_UP` выполняется один раз после расчёта. RUB имеет единичный курс.
Поддерживается и кросс-конвертация через RUB: результат в целых единицах целевой валюты находится
в `rounded_amount`; `amount_rub` доступен только при целевой RUB.

`effective_date` берётся из `ValCurs/@Date`, `requested_date` хранится отдельно. На выходных или
праздниках даты могут различаться; скачивание сегодня не превращает курс в сегодняшний.
`age_days(as_of)` возвращает знаковый возраст, `is_stale(..., max_age_days=3)` — явную проверку
давности. Три дня — настраиваемая политика приложения, не гарантия ЦБ. Отрицательный возраст
указывает на будущую дату действия: это также должен проверять потребитель. Автоматического
разрешения использовать устаревший/будущий курс или загрузить свежий нет.

Официальные курсы ЦБ — справочные, а не коммерческая котировка обменника, карты или поставщика бронирования.
В данных провайдера нужно сохранить исходную валюту/сумму и дату применённого курса.

## Реально записанный офлайн-снимок

- `data/sources/cbr-daily.xml` — фактический ответ публичного HTTPS endpoint.
- `data/sources/cbr-provenance.json` — URL, дата загрузки, официальная дата, SHA256 и метод.
- `data/cache/cbr/*.json` — воспроизводимый ответ нового HTTP-клиента.

Запись получена настоящим запросом через `CachedHttpClient(mode="record")`, затем проверена
через `replay`. Официальная дата снимка — **24 октября 2026**, 54 иностранные валюты плюс RUB.
Это зафиксированный снимок для демонстрации; наличие файла не означает актуальность для будущей даты.
Повторно записывать можно только явно в `record`, затем обновлять XML/provenance вместе.

Запрос с конкретной датой имеет другой ключ. В комплекте записан запрос без `date_req`;
для других дат сначала нужна собственная запись. Проверки не требуют сети:

```bash
cd backend
uv run pytest tests/test_http_cache.py tests/test_currency.py tests/test_cbr_snapshot.py
```

## Граница готовности

Кэш, валютное ядро и реальный снимок работают самостоятельно. Авиапоиск D2 через чат
проверен с настоящими ответами Aviasales в record и без сети в replay;
локальные записи исключены из Git. Подключение D3/D6 и применение конвертации
к их ценам выполняются отдельно. Закрытие всей D4 требует проверки настоящих
ответов в демо без сети; одни модульные тесты не подтверждают доступ поставщиков, наличие ключей
или целостность сценария всего продукта.

## Исправления review

D1 уже включён в main; конфликты `.env.example`, Makefile и README устранены.
Убраны отдельные переменные путей: используется единый DATA_DIR.
Права публичной записи устанавливаются через `os.chmod` после закрытия временного
файла, затем выполняется атомарная замена; Unix-only `os.fchmod` не требуется.
`load_cbr_rates` преобразует HTTP-ошибки, CacheMiss и ProviderRequestError
в единый безопасный CurrencyFetchError. Replay никогда не переключается на сеть.
Атрибуция ЦБ находится в `data/CBR-ATTRIBUTION.md`, отдельно от D5.
