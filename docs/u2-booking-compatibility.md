# У2 → D1/S3/S4/S5

Ветка `codex/U2-independent` включает D1 v0.1 (`cb97823`, PR #50) и опубликованные
S3/S4/S5 из main (`523c7ac`). Контракты, заглушки, схемы, примеры и их тесты взяты
из D1; настройки record/replay, клиенты данных, профили и собственные команды У2 сохранены.
Это проверка модулей данных, а не сквозной запуск агента, интерфейса или покупки.

## Проверка

```bash
make u2-compat-check   # выходы настоящих реализаций У2 → трансфер → таймлайн → валидатор
make u2-check          # полный pytest, источники, схемы, профили и автономный пример
make u2-demo           # данные У2 без чата и оплаты
```

Тесты используют `FlightTool` и `HotelSearchTool` У2, публичный `TransferRequest`,
`S4TransferTool`, `transfer_leg`, `build_timeline` и `validate_trip`. Проверяются:

- все 60 общих отелей с дневными и ночными рейсами для AYT, DXB и MLE;
- ночной прилёт к курорту, доступному только гидросамолётом: ожидание до утра
  передаётся в таймлайн и валидатор;
- сохранение физического hotel_id и отдельного offer_id, группы и её полной цены;
- преобразование UTC/московского времени в местный пояс без изменения момента;
- правила детских кресел, животных, предзаказа, длительности и возвратности;
- неизвестные часы отеля: события остаются неопределёнными, S5 просит уточнение,
  остальные ограничения продолжают проверяться;
- неподдерживаемый отель: явный `UnsupportedTransfer`, без подмены ценой/маршрутом заглушки.

## Доступ к S4 через фабрику У2

```python
from app.config import Settings
from app.contracts.tools import TransferRequest, Travelers
from app.tools.data_services import open_data_services
from app.tools.s4_adapter import transfer_leg

async with open_data_services(Settings(_env_file=None, cache_mode="replay")) as services:
    alternatives = await services.transfers.run(TransferRequest(
        airport="MLE",
        hotel_id="osm:way/133845532",
        pickup_at="2026-11-18T18:40:00Z",
        travelers=Travelers(adults=2, children_ages=[5]),
    ))
    leg = transfer_leg(alternatives[0])
    # services.transfer_base передаётся в validate_trip(..., base=...),
    # чтобы S5 мог предложить альтернативы и точную доплату из этой же базы.
```

`transport_mode="provider"` выбирает провайдер только для рейсов/поездов. S4 остаётся
сохранённой моделью с `is_synthetic=true`; реальные координаты и OSRM-расстояния
не подтверждают коммерческие тарифы, расписание, места или факт бронирования.

## Единый каталог D3/S4

| Направление | Отели У2 | Отели S4 | Совпадают |
|---|---:|---:|---:|
| AYT | 20 | 20 | 20 |
| DXB | 20 | 20 | 20 |
| MLE | 20 | 20 | 20 |
| Всего | 60 | 60 | 60 |

D3 строится из сохранённого `data/hotels/osm_hotels.json`, общего с S4.
ID, названия и координаты совпадают без нечёткого сопоставления по именам.
В S4 сохранены 136 вариантов и 40 OSRM-маршрутов; при унификации они не
пересчитывались. Для неизвестного ID или неверной пары аэропорт/отель
по-прежнему возвращается `UnsupportedTransfer`.

`scripts/fetch_hotels.py` воспроизводимо проецирует этот снимок в D3 без сети;
`--check` проверяет каталог, manifest и aliases без записи. Прежние raw-ответы
OSM и их manifest сохранены как архив, а не источник нового набора.
Активные синтетические правила, 1 440 отзывов и 60 профилей пересобраны для общего каталога.
Сведения о происхождении и порядок обновления — в [hotels.md](hotels.md).

Синтетическая ловушка D3 `far_transfer` с 120 минутами остаётся отдельной фикстурой:
S3/S5 берут время фактически выбранного S4-варианта. Аналогично D8 пока сравнивает перелёт с багажом и отель;
полная стоимость с трансферами и применёнными исправлениями относится к R2/R4.

Docker получает `data/transfers` и `TRANSFERS_PATH=/app/data/transfers/transfers.json`;
фабрика У2 разрешает базу и географические точки из одного корня `NA_MALDIVY_DATA_DIR`.
Проверка Compose-конфигурации не подтверждает сборку образа или Docker-smoke.
