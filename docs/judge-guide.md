# Проверка приложения за 5–10 минут

Это руководство относится к стандартному запуску из корня репозитория.
Нужны только Docker/Compose и браузер. API-ключи, подписки, локальные веса
модели, аккаунты поставщиков и пароль от сайта команды не требуются.

[Быстрый старт](../README.md#быстрый-старт) ·
[Происхождение данных](data-inventory.md) ·
[Требования и открытые пункты](submission-compliance.md)

## 1. Запуск

```bash
git clone https://github.com/ostrovok-hackathon-2026/na-maldivy.git
cd na-maldivy
cp .env.example .env
docker compose up --build
```

Дождитесь готовности `agent` и `app`. Откройте
[http://localhost:8080](http://localhost:8080). Логин и пароль не требуются.
Отдельная проверка [http://localhost:8080/health](http://localhost:8080/health)
возвращает HTTP 200 и `{"status":"ok","llm_provider":"fake"}`.

Первая сборка требует сети для публичных образов и Python-зависимостей.
Сами поисковые запросы с настройками из `.env.example` выполняются локально:
правила разбирают запрос, подготовленные каталоги и снимки дают данные,
шаблоны формируют ответ. Это проверка инструментов и интеграции; она не
демонстрирует качество внешней LLM.

Если репозиторий недоступен при `clone`, нужен доступ к командному репозиторию
в организации хакатона. Секреты, пароль сайта и сторонние приватные зависимости
для запуска не нужны.

## 2. Основной маршрут: Анталья → объяснение → даты → демо-заказ

Ориентир — 5–7 минут после готовности контейнеров. Копируйте запросы целиком,
отправляйте следующий после завершения предыдущего ответа.

| Шаг | Действие | Что должно произойти |
|---|---|---|
| 1 | Отправьте **«Из Москвы в Анталью 18 ноября 2026 на неделю вдвоём»**. | Появятся карточки отелей и панель Москва → Анталья, двое взрослых, 7 ночей. Для этих дат оба плеча отмечены как сохранённые котировки Aviasales. Сумма относится к группе и показанным компонентам. |
| 2 | В карточке раскройте **«Из чего складывается сумма»**. Добавьте два варианта к сравнению. | Видна разбивка перелётов, багажа, отеля и трансфера по прибытии; неизвестные доплаты перечислены отдельно. Таблица сравнивает текущие варианты, не меняя выбранный отель. |
| 3 | Отправьте **«Почему подходит первый отель?»**. | Ответ и блок фактов объясняют выбор на основе подготовленного профиля. Цитаты явно относятся к синтетическим отзывам, а не настоящим гостям. |
| 4 | Отправьте **«Сравни даты на 1–3 дня раньше»**. | Появится сравнение сопоставимых поездок с учётом группы, обоих рейсов, багажа, всех ночей и того же отеля. При отсутствии достаточных данных экономия не выдумывается. Исходная поездка не переносится автоматически. |
| 5 | Нажмите выбор у варианта без критической проблемы, затем **«Подтверждаю состав»**. | Откроется форма демонстрационного оформления. До оплаты это корзина, а не оплаченный заказ. Вариант с критической несовместимостью нельзя оплатить. |
| 6 | Оставьте вымышленные имена и даты рождения, проверьте количество путешественников, отметьте оба согласия. | Форма не требует номер банковской карты. Согласия об имитации оплаты и неоценённых расходах изначально не отмечены. |
| 7 | Нажмите **«Проверить отказ оплаты»**, затем **«Оплатить в демо»**. | Первый запрос показывает отказ без создания оплаченного заказа. Второй сохраняет демо-заказ. Никакого реального списания или бронирования не происходит. |
| 8 | Скачайте **демо-ваучер** и **календарь .ics**. Обновите страницу и откройте **«Мои поездки»**. | HTML-ваучер содержит состав и ограничения демонстрации; `.ics` — события поездки. Заказ и документы доступны снова в той же вкладке. |

Даты 18–25 ноября 2026 выбраны из сохранённого снимка. Это будущий сценарий
относительно даты подготовки 29.10.2026. При проверке после 18 ноября используйте
будущую дату: отсутствующие в снимке рейсы будут явно обозначенными моками,
и прежние цены/экономию ожидать нельзя. Прошедшая дата не должна превращаться
в якобы актуальный билет.

## 3. Ещё три проверки за 2–3 минуты

Для независимых сценариев нажимайте **«Новая поездка»**. Старый оплаченный
демо-заказ остаётся в **«Мои поездки»** текущей вкладки.

| Сценарий | Запрос / действие | Ожидаемый результат |
|---|---|---|
| Другой источник данных | **«Из Москвы в Дубай 18 ноября 2026 на неделю вдвоём»**. | У плеча туда явная отметка «ДЕМО-МОК», обратно — сохранённая котировка. Аэропорт DWC из неподходящего ответа не переименовывается в DXB. |
| Изменение плана после подбора | Найдите **«Из Москвы на Мальдивы 18 ноября 2026 на неделю вдвоём»**, затем отправьте **«Передумал: хочу поезд из Москвы в Петербург 18 ноября 2026, двое взрослых»**. | Карточки отелей перестают быть текущей выдачей; маршрут меняется на Москва → Петербург. Появляются карточки поездов с вокзалами, временем и классом. Цены и расписания помечены как демонстрационные; оформления железнодорожных билетов нет. |
| Исправление условий | После любого подбора откройте **«Изменить условия»**, измените число взрослых или дату и отправьте. | Сервер пересчитает выдачу; панель и карточки согласованы с новым запросом. Если показаны предположения, их принятие подтверждает только условия поиска и не начинает оформление. |

Если хотите увидеть **предположения**, в новой поездке отправьте
**«Из Москвы на Мальдивы в январе»**. Число взрослых, длительность и конкретный
день могут быть предложены для расчёта; они подписаны отдельно. В этом сценарии
рейсы вне ноябрьского снимка будут демонстрационными.

## Что здесь настоящее, а что демонстрационное

| Часть | Источник и граница |
|---|---|
| Отели | Названия, координаты и идентификаторы — OSM; каталог из 60 отелей Антальи, Дубая и Мальдив. Цены, наличие и условия — демо. |
| Авиакотировки | 47 очищенных ответов Aviasales Data API, записанных 28.10.2026. `recorded_at` — время записи, не подтверждение актуальности поставщиком. |
| Недостающие рейсы | Только явный режим `demo` дополняет корректно отсутствующие данные подписанным детерминированным мок-рейсом. Ошибка или повреждение источника не маскируются успешной выдачей. |
| Итоговая сумма | Расчёт известных компонентов на всю группу. Обратный трансфер, визы и прочие обязательные доплаты не оценены. |
| Трансферы | Подготовленная демонстрационная база; проверяются расписание, вместимость и совместимость по местному времени. |
| Отзывы и профили | 1440 синтетических отзывов и подготовленные профили 60 отелей. Настоящий LLM-прогон извлечения D7 не подтверждён. |
| Поезда | Синтетические расписания/модельные цены Москва ↔ Петербург. Доступ к настоящему API Яндекс Расписаний не проверен. |
| Оплата и документы | Реальный локальный код корзины, валидации, идемпотентности и SQLite, но платёж имитируется. Ваучер не является настоящим билетом или подтверждением поставщика. |
| Разбор запроса | По умолчанию правила и шаблоны `fake`; внешний OpenAI-совместимый API можно подключить отдельно. |

Наличие мест, окончательная цена покупки, реальный возврат и право въезда этим
демо не подтверждаются. Исходный семейный сценарий `u2-03` с бюджетом 150 000 ₽
не проходит: известные расходы в данных выше бюджета. Агент должен сообщить
об этом, а не создавать подходящий результат искусственно.

## Если что-то не работает

| Проблема | Проверка / действие |
|---|---|
| `docker` не подключается к daemon | Запустите Docker Desktop/Engine и повторите `docker compose up --build`. |
| Compose не понимает `env_file.required` | Используйте Docker Compose 2.24.4+; старый отдельный `docker-compose` не является требуемой командой. |
| Порт 8080 занят | Освободите его. Для необязательного альтернативного порта задайте `APP_PORT=8081` в `.env`, повторите запуск и откройте `http://localhost:8081`. |
| Образы/зависимости не скачиваются | Нужна доступность публичных Docker/PyPI-источников на этапе первой сборки. Уже собранное демо не требует ключей поставщиков или внешней модели. |
| Страница открывается, но чат недоступен | Откройте `/health`, выполните `docker compose ps` и `docker compose logs --tail 100 app agent`. Дождитесь `healthy`. |
| Обрыв ответа | Переписка и полученная часть ответа сохраняются. Используйте **«Повторить сообщение»** / **«Восстановить связь»** без перезагрузки. Не создавайте новый заказ для повторного получения ответа. |
| После перезапуска поиск завершился | Незавершённая серверная сессия находится в памяти. Нажмите **«Начать новый поиск»**; сохранённые SQLite-заказы и документы доступны через **«Мои поездки»** той же вкладки. |
| Новая вкладка не видит прежнюю поездку | Ссылки доступа хранятся в `sessionStorage` исходной вкладки; общей учётной записи и межустройственной истории в локальном демо нет. |

Остановить приложение, сохранив заказы:

```bash
docker compose down
```

`docker compose down --volumes` удаляет локальные демо-заказы и журнал сообщений;
это сброс данных, а не обычный способ остановки.

## Необязательные технические проверки

Для визуальной оценки достаточно сценария выше. Автоматический проход работает
внутри уже запущенного контейнера и не требует Python на компьютере:

```bash
docker compose exec -T agent python /app/scripts/check_running_three_destinations.py \
  --base-url http://app:8080 \
  --context /state/judge-three-private.json --output /state/judge-three-report.json
```

Ожидаемый итог — JSON с `status: passed`. Проверяются три направления,
объяснения отзывов, сравнение дат, отказ и успех демо-оплаты, повтор без дубля,
документы, запрет чужого доступа и смена оплаченной поездки на поиск поездов
при сохранении прежнего заказа. Создаются только вымышленные демо-заказы.

Отдельно проверить сохранение после перезапуска:

```bash
docker compose restart agent
docker compose up -d --wait --no-build
docker compose exec -T agent python /app/scripts/check_running_three_destinations.py \
  --base-url http://app:8080 \
  --context /state/judge-three-private.json --output /state/judge-three-report.json \
  --resume
```

Должны сохраниться те же заказы и SHA256 ваучеров/календарей. Context в `/state`
имеет права 0600 и содержит приватный доступ к тестовым заказам: его нельзя
публиковать, коммитить или прикладывать к issue. Безопасный report и stdout не
содержат идентификаторов доступа или ФИО. При обычном restart оба файла остаются
в томе; удалить их можно отдельно после проверки. Этот HTTP-прогон не заменяет
визуальную оценку, не доказывает браузерное восстановление и не сертифицирует
отсутствие сетевого трафика на уровне контейнерной сети.

Пока 18.11.2026 строго в будущем, проверяется сценарий сохранённых котировок;
затем скрипт автоматически выбирает `today + 28 дней` и честный `future_demo`
без ожидания старых сумм. Для явной будущей даты есть `--departure-date YYYY-MM-DD`.
`--resume` использует первоначальную дату из context.

Если на машине есть Python 3.11+, следующая read-only команда проверяет
конфигурацию и уже работающие `/` и `/health`, ничего не запускает и не изменяет:

```bash
python3 scripts/check_submission_package.py --base-url http://localhost:8080
```

Для разработчиков `make check` запускает линтер, тесты и изолированный Docker
smoke; нужны Python/uv и Node.js 22+. Это отдельная проверка исходников, а не
дополнительное условие старта приложения.

Старые отчёты в `eval/reports/` и [исторический срез](submission-readiness.md)
относятся к указанным в них коммитам/датам. Их счётчики тестов и прежние порты
не следует принимать за результат текущего запуска.
