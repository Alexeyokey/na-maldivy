# Аудит репозитория для проверки жюри

Проверки выполнены 29.10.2026 МСК: исходный аудит `ca76d20` и повторный
статический аудит рабочего дерева подготовки на его основе. Ниже зафиксированы
фактические проверки исходников и данных после описанных исправлений.
Это не сертификат безопасности, не проверка всех старых Git-коммитов и
не подтверждение завершённой сдачи. Актуальный маршрут проверки —
[руководство для жюри](judge-guide.md), запуск — [README](../README.md).

## Найденные замечания и состояние исправления

Здесь разделены проверенные изменения исходников и ещё ожидаемые проверки
runtime. Изменение smoke-скрипта само по себе не означает успешный Docker-прогон.

| Приоритет | Замечание на `ca76d20` | Минимальное исправление | Статус |
|---|---|---|---|
| P1 | У пяти локальных JPG-иллюстраций есть только общее упоминание Unsplash, без точного источника и автора | Заменить собственными иллюстрациями либо добавить проверяемые источники и условия использования | Выполнено: оригинальные SVG и README, XML/локальные ссылки/рендер проверены; активных ссылок на JPG нет |
| P1 | `.gitignore` исключает `.env`, но допускает `.env.local` и `.env.production` | Исключить `.env.*`, сохранив `.env.example`; исключить env-файлы из backend build context | Выполнено и проверено через `git check-ignore`; build-context exclusions добавлены |
| P1 | Docker smoke в `make check` запускает legacy `agent`/`gateway`, не проверяя стандартный `app` | Проверять отдельный экземпляр стандартного Compose и UI/API-путь без частного окружения | Исходники обновлены: отдельный стандартный проект, три направления, приватность и restart; успешный Docker-прогон ещё не подтверждён этим аудитом |
| P2 | Общая атрибуция описывает D5, а остальные источники разбросаны по каталогам | Добавить единый указатель по OSM/OSRM, CBR, Aviasales, синтетике и UI-ресурсам | Выполнено; происхождение и ограничения разделены, открытая лицензия Aviasales не заявлена |
| P2 | Старый инвентарь направляет на личную ветку и утверждает, что `main` содержит лишь шесть файлов данных | Указать стандартный запуск и включение полного набора в `62222c0` | Выполнено; размер данных повторно подсчитан после обновления атрибуции |
| P2 | README и исторические документы могут смешивать прежние порты, ветки и счётчики с текущим запуском | Сохранить историю отдельно, дать один основной маршрут проверки и обозначить дату доказательств | Основной маршрут и исторические доказательства разделены; ссылки проверены, пользовательский прогон итоговой сборки ожидает отдельного подтверждения |

Прежние JPEG добавлены коммитом `3ba5dbc`: `hotel-pool.jpg`, `room-cozy.jpg`,
`room-design.jpg`, `room-light.jpg`, `room-warm.jpg`. Ни tracked-исходники, ни
метаданные файлов не дают точного URL фотографий. Поэтому аудит не утверждает
ни наличие нарушения, ни подтверждённую лицензию на эти конкретные изображения.
Их замена не переписывает Git-историю. Новые SVG не содержат скриптов,
`foreignObject`, анимации, встроенных чужих изображений или внешних ссылок;
названия и происхождение зафиксированы в [README ресурсов](../frontend/dist/assets/README.md).

Статический разбор не нашёл новых секретов или неверных заявлений о настоящем
бронировании/LLM. Скан охватил текущие отслеживаемые и новые публичные файлы,
исключая удалённые изображения; значения потенциальных секретов не публиковались.
Полный `make check`, фактическая сборка и запуск обновлённого smoke ещё требуют
отдельного итогового отчёта; этот документ не объявляет их пройденными.

## Ограничения, которые нельзя скрывать в сдаче

- Демонстрационная оплата не списывает деньги, реальные брони и билеты не создаются.
- Подготовленные котировки не подтверждают актуальное наличие; неизвестные доплаты
  не превращаются в ноль. Синтетические расписания и условия должны оставаться помеченными.
- Настоящие Яндекс Расписания и LLM-извлечение D7 в этом аудите не вызывались.
- Внешние лицензии/условия поставщиков не исследовались заново. Достоверное
  происхождение данных само по себе не подтверждает любые права распространения.
- Полная сборка, запуск из чистого архива, браузер и восстановление после restart
  должны иметь отдельные доказательства конкретного итогового commit.
- Общедоступная ссылка на обязательное демо-видео отсутствовала в проверенном
  README. Наличие сценария записи не заменяет видеозапись.
- Финальный тег `submission` этим аудитом не создаётся. Его наличие, выбранный
  commit основной ветки и доступ жюри к командному репозиторию проверяются при сдаче.

Предыдущие отчёты в `eval/reports/` сохранены как датированные доказательства.
Их версии, количества тестов и скорость запуска относятся к указанным в них
срезам. Они не должны выдаваться за новый полный прогон после изменений.
