# Личный чат через Codex

Этот режим запускает сайт и backend только на вашем компьютере. Codex выполняет
запросы в облаке через существующий вход ChatGPT в установленном CLI; локальные
веса и GPU не нужны. Запросы расходуют доступные лимиты вашего аккаунта.
Это личный локальный интерфейс, который не подключает подписку к публичному VPS.
Для отдельного сценария единственного владельца есть
[закрытый серверный профиль](private-server-codex.md); локальный скрипт его не меняет.
Официальная [документация app-server](https://learn.chatgpt.com/docs/app-server#auth-endpoints)
различает локальные приложения и hosted services.

## Запуск

Нужны Node.js 22+, подготовленное окружение `backend/.venv` и установленный,
авторизованный через ChatGPT Codex. Для проверенного набора отключённых
инструментов адаптер принимает только CLI `0.163.0-alpha.11`. После обновления
CLI нужно заново проверить каталог инструментов и обновить ограничение версии.

Из корня репозитория:

```sh
python3 scripts/run_personal_codex.py
```

Откройте [личный интерфейс](http://127.0.0.1:18800). Вверху появится «Личный
Codex». Оба сервиса привязаны к `127.0.0.1`; скрипт не создаёт туннелей и не
меняет VPS. Ctrl+C или SIGTERM останавливает оба сервиса. Если порт занят,
доступны `--port 18810 --agent-port 18811`.

Авторизацией управляет CLI: скрипт не читает и не переносит файлы входа.
При необходимости выполните `codex login` самостоятельно. Проектный `.env`
в этом режиме не загружается, API-ключи для авиабилетов и языковой модели не
используются. По просьбе владельца профиль выбирает только `gpt-6-luna` с низкой
глубиной рассуждений (`low`), без подстановки более медленной модели.
Ускоренный платный service tier не включается. Пользовательский `config.toml`
игнорируется вместе с плагинами, правилами и остальными инструментами рабочего Codex.

## Что работает

Codex разбирает свободный текст, уточняет условия и формулирует ответы.
Поиск рейсов/отелей/трансферов, цены, проверки совместимости, D7/D8 и
оформление выполняет код проекта. Установка этого провайдера сама по себе
не является настоящим LLM-прогоном извлечения профилей D7.

Данные сохраняют явные отметки источника: записи Aviasales из D4 и моки,
расчётные отели/трансферы, синтетические отзывы и поезда. Оплата имитируется.
Заказы хранятся в исключённой из Git папке `artifacts/personal-codex-private/`
с ограниченными правами. Для оформления используйте вымышленные данные.

Встроенные инструменты Codex отключены: модель не получает терминал, файлы,
браузер, MCP или подагентов. Предлагаемые вызовы инструментов поездки
возвращаются как проверяемый JSON; исполняет их существующий реестр приложения.
Каждый ход выполняется в отдельной временной папке без истории рабочего
проекта. Ответ буферизуется до проверки формата и успешного завершения CLI;
пока он готовится, интерфейс показывает ход обработки. Таймаут или ошибка
авторизации не считаются успешным ответом Codex.

Локальный frontend проверяет адрес клиента, Host и Origin и добавляет внутренний
случайный токен только при обращении к backend. Токен не попадает в браузер или
аргументы процессов. Проверка здоровья loopback не использует HTTP-прокси.
`/health` через frontend показывает `llm_provider=codex_local` и число
успешных проверенных вызовов `codex_completed_calls`; это счётчик этого запуска,
без данных аккаунта и содержимого разговоров.

Проверка адаптера без аккаунта: `backend/tests/test_llm_codex_local.py`.
Проверки локального доступа: `backend/tests/test_personal_codex_access.py` и
`frontend/integration/personal-codex.test.mjs`. Настоящие проверки хранятся в
`eval/reports/personal-codex-2026-10-28/` отдельно от тестов с подставным CLI.
