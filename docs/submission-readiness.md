# Готовность сборки к сдаче — 28 октября 2026

Ветка `codex/submission-readiness` объединяет инструменты данных, orchestrator и
интеграционные исправления. Внешняя модель не используется. Это кандидат общей
сборки для проверки командой; открытые самостоятельные PR нужно согласованно
включать в main, чтобы не дублировать их изменения.

## Что готово к передаче

| Часть | Подтверждённое поведение |
|---|---|
| D1/D2/D3/D4/D5/S4 | Общие контракты и реестр, единые 60 отелей, 48 направлений, реальные авиакотировки через D4. |
| Переносимый кэш | 17 публичных записей Aviasales, SHA256-манифест и replay без ключа. Отдельный runtime-кэш и `.env` не публикуются. |
| D7 в чате | Проверенные числа и буквальные цитаты выбранного профиля; синтетика и baseline обозначены. |
| D8 в чате | Сопоставимые даты ±3 дня, оба рейса, багаж, все ночи, тот же отель/группа/условия и трансфер; строгий порог 5%. |
| O2 | Настоящие HTTP/SSE-трассы 10 исходных запросов; проверяются фактические поля, пустая выдача не даёт ложный успех. |
| Оформление | Приватная SQLite, тестовая оплата с отказом/успехом, идемпотентность, неизменяемый заказ, HTML-ваучер и `.ics`. |
| Репетиции backend | Пять последовательных проходов без модели, ключей и сети до ваучера/календаря. Данные и код фиксируются SHA256. |
| Запуск | Docker-образ с публичными данными внутри; агент без выхода в интернет, локальный API через входной прокси. |

Основной сценарий: Анталья 18–25 ноября 2026, двое взрослых. Котировки за место:
11 251 ₽ туда и 14 147 ₽ обратно. Первый вариант — 83 234 ₽ за показанные
компоненты. Сдвиг на 16 ноября в том же отеле: 71 086 ₽, разница 12 148 ₽,
14,59%. Обратный трансфер, визы и другие обязательные доплаты не оценены;
полную цену покупки эти числа не подтверждают.

`make check` прошёл 28.10.2026: Ruff, **1090 backend-тестов** и контейнерный smoke.

## Что остаётся команде

1. Включить выбранную общую сборку в сдаваемую ветку и договориться о порядке PR.
2. Подключить интерфейс к [готовой границе API/SSE](frontend-handoff.md), включая
   `checkout_pending`, данные путешественников, два подтверждения демо и загрузку файлов.
3. Выполнить пять проходов через пользовательский интерфейс до оплаты за ≤300 секунд
   и сохранить доказательства в `eval/demo-runs.json`. Текущие пять проверяют backend;
   весь пользовательский D9 ими не закрыт.
4. После заморозки — две репетиции защиты без правок между ними, слайды и видео.
5. Модель подключать отдельным изменением: текущий результат проверяет правила и
   инструменты. Настоящий LLM-прогон D7 и оценка моделей пока не выполнены.
6. Для настоящего Яндекса нужен ключ и отдельная проверка доступа. Переключатель
   источника и D4 подготовлены, но успешные mocks не доказывают настоящий доступ.

Не объявлены готовыми: реальное бронирование/оплата, наличие мест, реальная цена
отелей, пользовательский UI, сохранение всей незавершённой сессии после перезапуска,
качество внешней модели, реальные отзывы или проверка актуального права въезда.
