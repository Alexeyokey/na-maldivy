# D1: контракты инструментов v0.1

Базовая версия для интеграции: типы, заглушки, реестр и адаптер опубликованных данных S4.
Учтены [замечания к PR #50](https://github.com/ostrovok-hackathon-2026/na-maldivy/pull/50#issuecomment-6412625213).
Остальные источники подключаются в D2/D3/D5/D6, вызовы из `/api/chat` — в A2.
Выпуск v0.1 не объявляет завершённым согласование TripState и событий интерфейса на
[O1 (#3)](https://github.com/ostrovok-hackathon-2026/na-maldivy/issues/3).
Краткая таблица перехода временных моделей S4 — [d1-s4-migration.md](d1-s4-migration.md).

## Общие правила

- Идентификаторы — строки. Цены — неотрицательные целые рубли, без неявного округления дробных значений.
- `Place`: обязательный `kind` (`airport`, `hotel`, `city`), `iata`, название, координаты, IANA `timezone`.
  Для отеля `id` обязателен и равен `HotelOffer.hotel_id`; IATA остаётся кодом направления.
  Координаты гостиницы не заменяются координатами аэропорта. Для остальных точек `id` необязателен.
- `Travelers`: `adults`, `children_ages` (0–17 лет), `pets`. Должен быть хотя бы один взрослый.
- Перелёт и поезд ищутся в одну сторону. Обратное направление — отдельный запрос.
- `price_rub` перелёта/поезда — за всех путешественников в одну сторону. Багаж перелёта лежит отдельно
  в `baggage_price_rub` и тоже указан за всю группу.
- `HotelOffer.price_rub` — за всю группу и весь интервал `[check_in, check_out)`, без трансфера.
- `HotelOffer.hotel_id` — постоянный ID объекта; `offer_id` — конкретные даты, группа и тариф.
  Старый `id` принимается на входе как alias `offer_id`, а Python-свойство `.id` оставлено для миграции.
  В JSON выдаётся `offer_id`. Канонические OSM ID: `osm:node/123`, `osm:way/123`, `osm:relation/123`.
  Прежняя запись `osm:node:123` нормализуется при чтении. Авторские demo ID не выдаются за OSM.
- `Transfer.price_rub` — за всю группу и весь маршрут; повторно умножать на число пассажиров не нужно.
- Оценка стоимости направления включает перелёт туда и обратно и отель на `nights` за всю группу.
  Это ориентир для подбора, а не цена готового варианта с багажом/визой/трансфером.
- `DayPrice.price_rub` — минимальная цена перелёта в одну сторону за всю группу, без отеля.
- `departure_at`, `arrival_at`, `depart_at` в ответах — ISO 8601 с UTC-смещением местной точки.
  Входной `pickup_at` принимает любое UTC-смещение и переводится сервером в пояс отправления,
  сохраняя абсолютный момент и корректно меняя местную дату. Наивные даты-время отклоняются.
  Порядок отправления/прибытия проверяется по абсолютному времени.
- Календарные даты — `YYYY-MM-DD`, месяц календаря цен — `YYYY-MM`.
- Все ответы D1 помечены `is_synthetic=true`. Названия, цены, климат и правила заглушек не являются
  проверенными предложениями или справочной информацией о реальных объектах.
- Неизвестные поля входа отклоняются: опечатка аргумента не должна незаметно менять поиск.

## Инструменты

| Имя | Вход | Выход | Основные аргументы |
|---|---|---|---|
| `search_flights` | `FlightSearch` | `list[Flight]` | `origin`, `destination`, `departure_date`, `travelers`, `direct_only`, `max_price_rub` |
| `search_hotels` | `HotelSearch` | `list[HotelOffer]` | `destination`, `check_in`, `check_out`, `travelers`, `min_stars`, `refundable_only`, `max_price_rub` |
| `search_trains` | `TrainSearch` | `list[Train]` | `origin`, `destination`, `departure_date`, `travelers`, `seat_class` |
| `get_transfer` | `TransferRequest` | `list[Transfer]` | `airport`, `hotel_id`, `pickup_at`, `travelers` |
| `suggest_destinations` | `DestinationQuery` | `list[Destination]` | `month`, `origin`, `travelers`, `nights`, `budget_rub`, `min_water_temperature_c`, `visa_free_only` |
| `price_calendar` | `PriceCalendarQuery` | `list[DayPrice]` | `origin`, `destination`, `month`, `travelers` |

Варианты `seat_class`: `platzkart`, `coupe`, `sv`, `seated`.
Правила отеля `adults_only`, `pets_allowed`, `refundable` имеют значения `true` / `false` / `null`.
`null` означает неизвестность; её нельзя подменять разрешением или запретом. Неизвестные звёзды
и рейтинг тоже `null`, без подмены нулём. `reception_24h=true` означает круглосуточную работу,
`false` — известно, что работа не круглосуточная, `null` — неизвестно. Конкретное время закрытия
допускается только при `reception_24h=false`. Само `reception_closes_at=null` ничего не гарантирует.
`early_check_in_available=false` означает недоступность услуги, `null` — неизвестность; при `true`
цена может оставаться неизвестной. `early_check_in_price_rub=0` означает известную бесплатную услугу.
Это данные для будущего валидатора S5; жёсткое требование нельзя считать выполненным по `null`.
`check_in_time` и `check_out_time` тоже `time | null`, без неявных 14:00/12:00.
При неизвестном времени S3 оставляет событие и соответствующее ожидание неопределёнными,
а S5 возвращает `hotel_times_unknown` с предложением уточнить часы у отеля. Остальные проверки работают.
Синтетические отели задают свои модельные часы явно. У `DestinationQuery.origin` нет значения по умолчанию:
если город отправления неизвестен, агент должен его уточнить.

## Трансферы S4

- Публичный запрос задаёт только `airport`, постоянный `hotel_id`, aware `pickup_at` и группу.
  Модель не передаёт координаты или часовой пояс: сервер находит их в выбранном каталоге.
  Внутренний `TransferQuery` с полными `Place` сохранён для адаптеров и нормализует время в пояс отправления.
- `get_transfer` возвращает альтернативы: сначала `available=true`, внутри группы — без известных
  запретов `pets_forbidden`/`child_seat_missing`, затем по `price_rub` и `id`.
  Неподдерживаемый маршрут вызывает `UnsupportedTransfer`, наследник `ValueError` из
  `app.tools.errors`; `[]` означает отсутствие предложений на поддерживаемом маршруте.
- `pickup_at` — момент, когда группа готова отправиться; `depart_at` — ближайшее предложенное
  отправление в часовом поясе начальной точки. Оно не раньше `pickup_at` по UTC. При `available=true`
  оба момента совпадают; при `false` возможны будущее отправление или `null`, если отправление не найдено.
- `available` описывает отправление по модельному расписанию, не подтверждение реального наличия мест,
  соответствия требованиям животных/детей или факта бронирования.
- `hours` обязательно: `null` разрешён только для известной круглосуточной работы. Иначе
  `{"from":"06:00:00","to":"18:00:00"}` — ежедневное местное полуоткрытое окно `[from, to)`.
  Если `from > to`, окно переходит через полночь. Равные границы запрещены: для 24 часов есть `null`.
  Неизвестное расписание нельзя маскировать под круглосуточное; адаптер должен явно сообщить о неполноте.
- `mode`: `taxi`, `minivan`, `shuttle`, `bus`, `metro`, `boat`, `seaplane`, `flight_speedboat`.
  Последний — составной трансфер «внутренний рейс + катер», без выдуманных времён отдельных сегментов.
  S4 `private_minivan` преобразуется в `minivan`, `speedboat` — в `boat`.
- `vehicles` — число машин для частного трансфера; у транспорта с оплатой за пассажира может быть `null`.
  Итоговый `price_rub` уже включает всю группу и все нужные машины, повторно умножать его нельзя.
- `pets` и `child_seat` — `true` / `false` / `null`; неизвестное не означает запрет или разрешение.
  Возраст/вид животного и обязательность кресла не угадываются из этих признаков.
- `luggage_limit` — текстовое ограничение багажа или `null`; `prebook_hours` — число часов предзаказа,
  `0` означает известное отсутствие предзаказа, `null` — неизвестность; `distance_km` — расстояние или `null`.
- `issues` — замечания по текущему запросу: `unavailable_at_pickup`, `pets_forbidden`, `pets_unknown`,
  `child_seat_missing`, `child_seat_unknown`, `extra_vehicle`, `night_surcharge`, `long_transfer`,
  `prebook_required`, `luggage_limit`. Например, запрет животных становится проблемой только для группы с питомцем.
- В демонстрационной тарифной политике такси вмещает 4 человека, минивэн — 6; младенцы учитываются
  в вместимости машины. У транспорта с оплатой за человека дети младше двух лет едут бесплатно.
  Это согласуемая demo-политика, не тариф или юридическое правило реального перевозчика.

## Использование без агента

Из каталога `backend`:

```python
import asyncio
from app.config import Settings
from app.tools import create_tools, run_tool, tool_specs

async def main():
    tools = create_tools(Settings(tools_mode="stub", llm_provider="fake"))
    flights = await run_tool("search_flights", {
        "origin": "SVO",
        "destination": "AYT",
        "departure_date": "2026-11-18",
        "travelers": {"adults": 2, "children_ages": [5]},
    }, tools=tools)
    print(tools["search_flights"].output_adapter.dump_json(flights).decode())
    # Эти спецификации принимает существующий LLMClient.complete(..., tools=...).
    specs = tool_specs(tools)
    print([spec.name for spec in specs])

asyncio.run(main())
```

`Tool` описывает `name`, `description`, `input_model`, `output_adapter` и `async run(input)`.
`run_tool` проверяет JSON-аргументы через входную pydantic-модель, затем проверяет результат через
`output_adapter`. Для прямого вызова `tool.run()` сначала создайте экземпляр входной модели.

`TOOLS` — готовый реестр заглушек без чтения `.env`. Для приложения используйте `create_tools(settings)`:
он учитывает `TOOLS_MODE`. Режим `real` пока явно выдаёт `NotImplementedError`, вместо подмены настоящих
ответов синтетическими. A2 должен передавать полученный реестр в диспетчер и в `tool_specs`.

Ошибки границы: неизвестное имя — `KeyError`, неверные аргументы или ответ — `ValidationError`.
Перевод этих ошибок в понятный ответ пользователю относится к A2.

Подключение опубликованного S4 вместо заглушки трансфера:

```python
from app.tools.registry import run_tool, tool_specs
from app.tools.s4_adapter import S4TransferTool, transfer_leg

tools = {"get_transfer": S4TransferTool()}
transfers = await run_tool("get_transfer", {
    "airport": "MLE",
    "hotel_id": "osm:node/4455235191",
    "pickup_at": "2026-11-18T18:40:00Z",  # 23:40 в Мале
    "travelers": {"adults": 2},
}, tools=tools)
leg = transfer_leg(transfers[0])  # участок для S3 build_timeline / S5 validate_trip
specs = tool_specs(tools)
```

Адаптер использует OSM-факты из `data/hotels/osm_hotels.json` и `data/transfers/airports.json`,
сохраняет группу, цену, расписание и ограничения S4. Коммерческие условия S4 синтетические,
поэтому ответы помечены `is_synthetic=true`, включая маршруты с расстоянием OSRM.
Выбор адаптера явный: стандартный `TOOLS` остаётся детерминированным демо-каталогом.

## Заглушки и воспроизводимость

Заглушки не используют сеть, ключи, LLM или текущее время. Одинаковый запрос возвращает одинаковые
данные; вызовы возвращают новые объекты, которые можно изменять, не портя следующие ответы.
Поддерживаемые маршруты и тестовые ловушки описаны в `backend/app/tools/stubs.py` и проверены тестами.
Пустой результат для неизвестного направления — нормальное поведение. Неподдерживаемый трансфер
вызывает `UnsupportedTransfer(ValueError)`, чтобы отличать отсутствие вариантов от неизвестного маршрута.

Демо-каталог:

- Перелёты: SVO/MOW или LED ↔ AYT, DXB, MLE. MOW в авиапоиске означает SVO.
  Два прямых рейса в день: 09:00 и 23:30. Например, SVO 18 ноября 23:30+03:00 → DXB 19 ноября 06:00+04:00.
- Отели: четыре синтетических предложения на направление. Есть невозвратный бюджетный отель
  с ресепшеном до 22:00, семейный, adults-only и премиальный. Фильтры учитывают детей и животных.
- Поезда: Москва ↔ Петербург. Здесь SVO преобразуется в город MOW; у LED используются городские координаты.
- Публичные трансферы: аэропорт → отель в одной демо-локации AYT/DXB/MLE.
  Берите `hotel_id` из `search_hotels`; аэропорт и физические точки резолвятся на сервере.
  В Мале запрос в 23:40 показывает доступные альтернативы и недоступный сейчас гидросамолёт
  с отправлением на следующий день в 06:00. Заглушки не утверждают реальную доступность транспорта.
- Направления: три синтетических профиля с климатом по 12 месяцам. Календарь цен согласован
  с минимальными ценами `search_flights` и покрывает все дни выбранного месяца.

## JSON Schema и проверки

```bash
make schemas     # обновить contracts/schema/tools.json
make tool-examples # обновить JSON-примеры всех инструментов и кейсов S4
make check-fast  # линтер и тесты, включая проверку актуальности выгрузки
make check       # дополнительно Docker и HTTP smoke, если Docker запущен
```

`contracts/schema/tools.json` — общий JSON Schema с разделяемыми `$defs`. В `properties` лежат
шесть инструментов, у каждого — схемы `input` и `output`. Объект вида
`{"search_flights": {"input": ..., "output": ...}, ...}` можно целиком проверить этой схемой.
Это описание и формат тестовых примеров, а не новый HTTP endpoint.
Воспроизводимые пары запрос/ответ — `contracts/examples/tools.json`; отдельные сценарии S4 —
`contracts/examples/s4-transfers.json`. Проверка примеров повторно выполняет заглушки и сравнивает файлы.

Для LLM используется только входная схема каждого инструмента. `tool_specs()` разворачивает локальные
`$ref` и удаляет `$defs`, сохраняя ограничения, обязательность и `null`. Рекурсивные, внешние или
неразрешимые ссылки отклоняются явной ошибкой. Общая выгрузка для разработчиков сохраняет `$defs`.
Тест с подставным HTTP-сервером проверяет передачу схем через существующий OpenAI-совместимый клиент.
Прогон на внешнем провайдере и выбранной модели остаётся частью A3; локальный HTTP-тест не доказывает
поддержку всех возможностей JSON Schema конкретным провайдером.

## Решения для O1

1. Утвердить шесть имён инструментов и поля запросов/ответов.
2. Согласовать `Travelers` с полями TripState (R1), включая возраст детей и животных.
3. Подтвердить единицы цен и отдельный учёт багажа с R2/S1.
4. Подтвердить работу с IATA городов/аэропортов и локальным временем с D2/S3.
5. Подтвердить список полей S4 и точный смысл расписания/доступности, общие ошибки и требования S5.
6. Утвердить общий гостиничный набор D3/S4: формат ID един, но совпадают только 6 из 72 объектов
   независимого D3 с 60 объектами S4. Наличие адаптера не создаёт отсутствующие маршруты.
7. Дальнейшие изменения v0.1 сопровождать обновлением моделей, выгрузки и примеров в одном PR.
