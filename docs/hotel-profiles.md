# D7: профили по синтетическим отзывам

60 общих с D3/S4 hotel_id, 24 текста на отель (1440 всего), по шесть в сегментах
family/couple/business/pets. Тексты — авторские шаблоны Codex с явной пометкой
синтетики, не отзывы настоящих гостей и не пакетная генерация внешним API.
Исходные OSM-точки и правила D3 v3 этот скрипт никогда не перезаписывает.

`HotelOffer.review_profile` в публичном `search_hotels` содержит типизированный
профиль: плюсы/минусы по сегментам, количество упоминаний/отзывов, дословные
цитаты с review_id, SHA256 корпуса и происхождение извлечения.
Отсутствующий профиль — null, повреждённый профиль — явная ошибка. Профиль
другого hotel_id и несогласованные числа отклоняются. Профили не являются
доказательством реальных качеств отеля и не заменяют жёсткие правила D3/S5.

Проверенный baseline извлекает только известные фразы из текстов, не читая
annotations. Скрипт сверяет его с разметкой, агрегирует числа обычным кодом
и проверяет сохранённые JSON. Это узкая тестовая baseline-модель, не универсальный
анализатор произвольных отзывов. extraction.model=null и live_model_run=false.

Шаблоны согласованы с синтетическими правилами D3: у `adults_only=true`
семейный отзыв содержит отрицательное упоминание запрета проживания с детьми,
а не положительную рекомендацию для детей. Аналогично отзывы о питомцах
следуют `pets_allowed`. Это согласованность двух демонстрационных наборов,
а не проверка настоящих правил OSM-отеля. Условия возврата эти отзывы не описывают.
Число текстов и их ID сохраняются; изменение текста меняет SHA256 корпуса.
Повторная генерация оставляет неизменившиеся файлы нетронутыми, а `--check`
проверяет точные воспроизводимые UTF-8 байты корпусов и профилей без записи.

```sh
make d7-check
make d7-build
# только проверка, без записи/сети:
cd backend
uv run --locked --offline python ../scripts/build_hotel_profiles.py --check
```

Есть отдельный путь извлечения через существующий LLMClient: недоверенный текст
отделён от инструкции, проверяются схема, покрытие review_id, принадлежность
отеля/сегмента и буквальное присутствие каждой цитаты. Counts никогда не принимает
от модели. FakeLLMClient проверяет этот интерфейс, но не считается live-прогоном.
Семантическое качество настоящей модели нужно измерить отдельно против annotations.

После настройки LLM_PROVIDER/LLM_API_KEY/LLM_MODEL_MAIN (при необходимости FAST):

```sh
cd backend
uv run --locked --offline python ../scripts/build_hotel_profiles.py --mode llm \
  --allow-live-llm --hotel-id osm:node/11182077737
```

Это явное сетевое действие. Результаты по умолчанию идут в `data/hotel_profiles_llm/`,
не заменяя проверенный lexical baseline. Параметр --output-dir позволяет выбрать
другое место. Без флага разрешения, настройки провайдера или сохранённого корпуса
скрипт завершается до вызова модели. Прогон реального провайдера не выполнен:
в локальном проекте нет ключей и настроенной модели. D7 остаётся частичной по этому пункту.

PR основан на D3; после слияния D3 нужно перевести его базу на main. Схема и примеры
D1 обновлены вместе с новым необязательным полем; поведение S4/S3/S5 сохранено.
