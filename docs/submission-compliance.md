Проверка конфигурации не строит и не запускает контейнеры:

```bash
python3 scripts/check_submission_package.py
# После запуска стандартного приложения:
python3 scripts/check_submission_package.py --base-url http://localhost:8080
```

Скрипт печатает только безопасный отчёт, никогда полный `docker compose config`
с приватным окружением. Его `scope=default_docker_package`,
`handoff_certified=false`: технический успех не означает создания тега,
переноса в main или появления видео. Необязательные resource caps не блокируют
результат проверки. Доступность внешних источников подтверждена отдельным снимком,
а проверка конфигурации пригодна для работы без внешней сети.

## Проверенный локальный запуск

Первый чистый запуск — `1419c92`; на нём `make check` прошёл: Ruff,
1268 backend-тестов, 130 unit- и 11 HTTP-тестов frontend, Docker smoke.
После найденной проблемы восстановления документов изменены только frontend
и его тесты (`1c1a023`): 135 unit + 11 HTTP, синтаксис и независимый разбор
пройдены. На новом чистом архиве `1c1a023` повторены сборка, три направления,
перезапуск и настоящий браузер. Backend, данные и Compose между прогонами
не менялись. Новый путь на 8080 проверен независимо от старых профилей.

- Поиск, D7/D8, выбор, отказ/успех демо-оплаты и документы: AYT/DXB/MLE — 3/3.
- После перезапуска `agent` все три заказа и SHA256 ваучеров/календарей сохранились.
- В браузере проверены поиск → выбор → два согласия → тестовая оплата →
  обновление страницы → повторное открытие заказа и скачивание обоих документов.
- Исправлена потеря кнопки документов после исчезновения поисковой сессии.
  В браузере проверены реальный restart контейнера, два reload, скачивание
  ваучера/календаря и доступ из истории после начала нового поиска.
- В образе 247 файлов данных (3 082 896 байт), SQLite имеет права 0600;
  `uv`, `gcc`, `make`, pytest и Ruff отсутствуют в backend runtime.

Финальные отчёты: `clean-start.json`, `package-http.json`,
`three-destinations-final.json`, `three-destinations-final-after-restart.json`,
`local-ui.json`, `automated-checks.json` в каталоге доказательств ниже.
Первый прогон стал доступен не позднее 31,634 с, повторный — 9,863 с. Это
верхние границы до первого успешного HTTP-наблюдения с готовыми базовыми
образами/кэшем, не обещание холодной сборки за такое же время. Исходные
снимки `*-baseline.json` и `static-audit-before-runtime.json` сохранены.
