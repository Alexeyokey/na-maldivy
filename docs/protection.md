# «Отпуск под защитой»: предложение фичи

> Это **отдельный, необязательный** модуль. Он не меняет поведение агента и по умолчанию выключен.
> Если команда решит, что фича не нужна, закройте PR. Как убрать её после мержа, описано в конце.

## Идея

Рейсы сейчас часто переносят и отменяют. Когда рейс сдвигается, «уплывает» весь отпуск: сгорает первая ночь в отеле, водитель трансфера уезжает, приходится покупать новый билет. Человек в этот момент стоит в аэропорту и в стрессе: звонит в авиакомпанию, отель и страховую, собирает справки и сначала платит за всё сам, а потом ждёт, одобрят ли выплату.

Сегодня на рынке есть страховки от задержек рейсов, например «Вояж» у ЕВРОИНС. Они платят **фиксированную** сумму за задержку больше 3 часов или отмену. Реальную пересборку поездки (новый билет, сгоревшую ночь, повторный трансфер) они не оплачивают, и делать её клиенту приходится самому.

**Наше предложение.** Полис продаётся вместе с поездкой, заранее. При сбое бот сам:

1. фиксирует отмену или задержку;
2. находит новый рейс, предупреждает отель (бронь не снимут как no-show) и переносит трансфер;
3. считает, во что обошлась пересборка, и показывает, сколько покрывает страховка;
4. после **одного «да»** клиента переоформляет поездку и сам отправляет заявку в страховую с готовым пакетом документов.

Пересборку оплачивает Островок, а страховая возмещает эти расходы ему. Клиент ничего не платит из своего кармана.

> **«Один полис — и отпуск не сломать: при сбое бот сам всё пересоберёт, а оплатит страховая».**

Бот ничего не покупает без подтверждения: перебронирование тратит деньги. Это тот же принцип, что и у основного агента (оформление только после явного «да»).

## Как посмотреть

Без сети и ключей:

```bash
make protection-demo                    # отмена рейса туда: новый билет, сгоревшая ночь, трансфер
make protection-demo ARGS="--inbound --delay 20"   # задержка обратного рейса на 20 ч: лишняя ночь в отеле
make protection-demo ARGS="--delay 2"   # задержка меньше 3 ч: не страховой случай, но бот всё равно всех предупредил
```

Через API нужно включить флаг `PROTECTION_ENABLED=true` в `.env`, оформить поездку через `/api/chat`, а дальше:

| Запрос | Что делает |
|---|---|
| `GET /api/protection/{session_id}/offer` | Предложение полиса: цена (4% от поездки), лимит, что покрывает |
| `POST /api/protection/{session_id}/policy` `{"consent_data_transfer": true}` | Оформить полис; без согласия на передачу данных страховой будет 409 |
| `POST /api/protection/{session_id}/disruption` `{"leg": "outbound", "kind": "cancel"}` | Сбой рейса → план пересборки, который ждёт подтверждения |
| `POST /api/protection/{session_id}/confirm` `{"plan_id": "PLAN-…"}` | «Да»: переоформление и заявка в страховую |

## Где код

Всё лежит в `backend/app/protection/`, агент о модуле не знает:

| Файл | Что внутри |
|---|---|
| `models.py` | Полис, сбой, план пересборки, заявка. Порог страхового случая — 3 часа |
| `recovery.py` | Пересборка: поиск нового рейса через `search_flights`, последствия для отеля и трансфера, расходы |
| `service.py` | Сценарий целиком: предложение → полис → сбой → подтверждение → заявка, плюс тексты для клиента |
| `insurer.py` | **Имитация** страховой (`MockInsurer`) и интерфейс `InsurerClient` для настоящей интеграции |
| `api.py` | Эндпоинты `/api/protection/…` |

Тесты лежат в `backend/tests/test_protection.py`, демо — в `backend/scripts/protection_demo.py`.

## Честно об ограничениях

- **Страховая ненастоящая.** Партнёрства и API нет, `MockInsurer` одобряет формализуемые случаи в пределах лимита. Цена полиса (4%, минимум 990 ₽) и лимит (60% стоимости поездки, минимум 50 000 ₽) условные.
- **Сбой задаётся вручную.** В проде его присылала бы авиакомпания или сервис статусов рейсов.
- **Финансовый риск.** Если Островок оплачивает пересборку до решения страховой, он рискует на случай отказа. Поэтому автоматически покрываются только случаи, которые подтверждаются данными (отмена или задержка по данным перевозчика), и только в пределах лимита полиса.
- **Персональные данные.** Без явного согласия клиента на передачу данных брони страховой полис не оформляется.

## Этапы развития

1. Продажа полиса вместе с поездкой, уведомления о сбоях, автоматическая заявка в страховую.
2. Автоматический перенос брони отеля и трансфера.
3. Полуавтоматическое перебронирование билетов: бот готовит варианты, клиент подтверждает в один клик.

## Как убрать

Фича — один коммит. Убрать её можно на любом этапе:

- **До мержа:** закрыть PR. В ветку сдачи ничего не попадёт.
- **После мержа:** откатить этот коммит одной командой, она создаст обратный коммит:
  ```bash
  git revert <хеш коммита «Отпуск под защитой»>
  ```
  Или вручную:
  1. удалить `backend/app/protection/`, `backend/tests/test_protection.py`, `backend/scripts/protection_demo.py`,
     `make/protection.mk` и этот файл;
  2. удалить строки с пометкой `protection` в `backend/app/main.py` (блок из трёх строк с `if settings.protection_enabled`),
     `backend/app/config.py` (одна строка) и `.env.example` (две строки).
     Найти их: `grep -n "protection" backend/app/main.py backend/app/config.py .env.example`.
- **Просто выключить, ничего не удаляя:** `PROTECTION_ENABLED=false` (так по умолчанию).
  Адресов `/api/protection` не будет, агент и интерфейс работают как раньше.
