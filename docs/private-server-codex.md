# Личный Codex на закрытом сервере

Режим `codex_private` предназначен для одного владельца. Сайт на
[https://201.8.90.64](https://201.8.90.64) закрыт отдельным паролем, а backend
запускает официальный Codex CLI от имени владельца. Веса модели на VPS не
устанавливаются: вычисления выполняет сервис Codex. Расходуются лимиты аккаунта.
Пароль сайта нельзя передавать судьям, участникам команды или другим посетителям:
это изменит согласованный сценарий личного использования.

Это описание технической реализации, а не гарантия соответствия всем условиям
сервиса. Официальная документация описывает
[`codex exec` и авторизацию на доверенных приватных runners](https://learn.chatgpt.com/docs/non-interactive-mode#authenticate-in-automation),
а также [вход на удалённых устройствах](https://learn.chatgpt.com/docs/auth#login-on-headless-devices).
Эти инструкции сами по себе не дают явного исключения для личного браузерного
интерфейса на размещённом сервере. Документация
[app-server](https://learn.chatgpt.com/docs/app-server#auth-endpoints) отдельно
ограничивает применение его авторизации в hosted services. Замена app-server
на CLI не является автоматическим разрешением на публичный сервис. Для доступа
других пользователей нужны подходящие официальные условия интеграции.

## Что проверено

Срез подготовки от 28 октября 2026 года:

- HTTPS с обычной проверкой доверия сертификата работает; HTTP перенаправляет
  на HTTPS и не запрашивает пароль по незашифрованному соединению.
- Без правильного пароля недоступны страницы, `/config.js`, `/health`, чат,
  сессии и документы заказов. После входа проверены сценарии трёх направлений
  на прежнем провайдере `fake`.
- Реализованы `codex_private`, проверка внутреннего nonce, ограничения
  Host/Origin и выбор только Luna. Тесты доступа и CLI-адаптера проходят.
- Linux CLI `0.163.0-alpha.11` скачан из официального пакета; целостность
  проверена. Тест без аккаунта подтвердил отсутствие встроенных инструментов
  модели и невозможность исполнить навязанный вызов команды.
- Владелец завершил свежий официальный device login на VPS. Настоящий короткий
  ответ Luna прошёл за 10,051 с. После включения закрытого сайта свободный
  запрос Москва → Анталья, 18.11.2026, 7 ночей, двое, 120 000 ₽ прошёл через
  HTTPS за 15,661 с: два проверенных вызова Codex, варианты 83 234 и 112 856 ₽.
  Эти времена относятся к двум измеренным запросам, не являются гарантией.
- В фактическом Docker-образе отдельно повторён тест изоляции без аккаунта:
  каталог встроенных инструментов пуст, навязанный `exec_command` не исполнен.
- Запросы без пароля и с постороннего Origin отклонены; счётчик вызовов модели
  при них не изменился. Все сервисы запущены, внутренние порты не публикуются.
- Шесть старых демо-заказов для трёх направлений сохранились после обновления;
  содержимое заказов, ваучеров и календарей совпало по хешам.

[Обезличенные результаты проверок](../eval/reports/private-codex-server-2026-10-28/report.json).
Полный браузерный проход нового закрытого VPS в этом отчёте не заявляется:
автоматизированный браузер не поддержал окно HTTP Basic Authentication.
Проверка настоящего нового чата выполнена по HTTPS API. Для входа используйте
обычный браузер и отдельные логин/пароль сайта; не добавляйте их в URL.

## Как проходит запрос

```text
Браузер владельца
  → HTTPS :443, Caddy, отдельный пароль сайта
  → внутренний Nginx edge
  → Node frontend, проверка Host/Origin, добавление серверного nonce
  → FastAPI agent, проверка nonce
  → изолированный codex exec
  → облачная модель gpt-6-luna, reasoning low
```

Снаружи публикуются только 80/443 шлюза; SSH остаётся отдельным административным
каналом. Порты Node, FastAPI и внутреннего Nginx не публикуются на хосте.
Caddy требует пароль на всех путях, включая API и документы. Он удаляет
`Authorization` перед передачей запроса внутрь. Node передаёт в backend только
разрешённые заголовки и сам добавляет `x-local-codex-token`; присланное браузером
значение этого заголовка не используется.

Личный серверный frontend принимает Host `201.8.90.64`. Если Origin присутствует,
он должен равняться `https://201.8.90.64`; запросы с `Sec-Fetch-Site: cross-site`
отклоняются. Отсутствие Origin допустимо для служебных проверок, поэтому эти
проверки не заменяют пароль Caddy. Backend требует nonce на всех HTTP-маршрутах,
включая `/health` и CORS preflight.

Сертификаты Caddy хранятся в постоянном томе и обновляются автоматически.
IP-сертификат короткоживущий: доступность ACME и сохранность тома нужны в течение
всего времени работы сайта. В конфигурации задан `default_sni 201.8.90.64`,
чтобы обычные клиенты, подключающиеся по IP без SNI, получали правильный сертификат.
Проверки не должны отключать проверку TLS.

## Compose и настройки процессов

Применяются три файла в указанном порядке:

1. `deploy/vps/compose.yml` — базовое приложение и постоянный том заказов.
2. `deploy/vps/private-compose.yml` — HTTPS, пароль, снятие публикации edge.
3. `deploy/vps/codex-compose.yml` — личный CLI runtime и обновлённые образы.

Для серверного запуска нужны следующие параметры Compose. Это пути и имена
образов; секретные значения в командную строку не подставляются.

| Переменная | Назначение |
| --- | --- |
| `NA_PRIVATE_AGENT_IMAGE` | Образ backend с обновлённым приложением. |
| `NA_PRIVATE_WEB_IMAGE` | Образ frontend с режимом `PRIVATE_SITE_MODE`. |
| `NA_PRIVATE_SOURCE_DIR` | Абсолютный путь к подготовленным исходникам личной сборки на VPS. |
| `NA_CODEX_RUNTIME_DIR` | Абсолютный путь к проверенному Linux runtime официального Codex CLI. |
| `NA_CODEX_AUTH_DIR` | Отдельный защищённый каталог состояния и входа Codex на VPS. |
| `NA_PRIVATE_RUNTIME_ENV` | Защищённый серверный файл окружения с внутренним nonce. |
| `NA_PRIVATE_CADDYFILE` | Путь к серверной копии `private.Caddyfile`. |
| `NA_PRIVATE_AUTH_FILE` | Путь к файлу bcrypt-хеша пароля сайта для Caddy. |

Backend запускается через фабрику `app.personal_codex:create_app`:

```text
uvicorn app.personal_codex:create_app --factory --host 0.0.0.0 --port 8000 --workers 1 --no-access-log
```

Фабрика создаёт `Settings(_env_file=None)`: проектный `.env` не загружается.

В backend задаются `LLM_PROVIDER=codex_private`, `CODEX_BINARY`, `CODEX_HOME` и
`CODEX_LOCAL_TOKEN`. Настройки основной и быстрой модели допускают только
`gpt-6-luna`; другие имена отклоняются при запуске. В frontend задаются
`PRIVATE_SITE_MODE=1`, `AGENT_URL=http://agent:8000` и тот же `CODEX_LOCAL_TOKEN`.
`LOCAL_ONLY=1` относится к отдельному локальному режиму и несовместим с этим
серверным профилем. Приватный контейнер агента получает исходящий доступ к Codex,
но по-прежнему не публикует HTTP-порт.

Проверки здоровья тоже проходят границы доступа: backend получает nonce из
своего окружения, а web и edge отправляют Host `201.8.90.64`. Исходные проверки
`/health` без этих настроек будут отклоняться; их нельзя обходить открытием
неавторизованного внешнего маршрута.
Для web используется `node:http`: установленный Node 22 не сохранил Host,
заданный через `fetch`, что подтвердил реальный запуск контейнера.

## Три независимых секрета

| Секрет | Где хранится | Кто использует |
| --- | --- | --- |
| Пароль сайта | На Mac: `artifacts/private-access/site-access.json`, права `0600`; на VPS хранится только bcrypt-хеш в `/srv/na-maldivy/secrets/site-users.caddy`, права `0400`. | Браузер владельца и Caddy. |
| Внутренний nonce `CODEX_LOCAL_TOKEN` | `/srv/na-maldivy/secrets/private-runtime.env`, права `0600`. Случайное значение не короче 32 символов. | Только Node и backend. |
| Сохранённый вход Codex | Отдельный `/srv/na-maldivy/secrets/codex-auth/`, права каталога `0700`, владелец — пользователь CLI в контейнере. | Только официальный CLI; каталог монтируется в его `CODEX_HOME`. |

Локальный файл с данными сайта находится в исключённом из Git `artifacts/`.
Абсолютный путь на текущем Mac:
`/Users/alexvetrov/Documents/ChatGPT/Ресерч проектов/na-maldivy-orchestrator-check/artifacts/private-access/site-access.json`.
Значения пароля и nonce не публикуются в документации, отчётах, Git, URL,
аргументах процессов или браузерном коде. Перед выводом диагностики Compose
нужно учитывать, что развёрнутая конфигурация может содержать окружение с nonce.

Вход Codex не хранится в образе и не берётся из локального аккаунта Mac.
CLI должен иметь возможность обновлять собственную авторизацию в защищённом
каталоге. Этот каталог нельзя подключать к заданиям из PR, публичным CI jobs
или непроверенному коду. Приложение не читает и не отдаёт содержимое auth-файлов.

## Свежий вход на сервере

После подготовки контейнера администратор запускает в нём от имени обычного
пользователя CLI, с тем же защищённым `CODEX_HOME`, который использует backend:

```sh
codex login --device-auth
```

Владелец открывает выданную CLI официальную ссылку, входит в свой аккаунт и
вводит одноразовый код. Если требуется, он предварительно включает device code
login в настройках безопасности ChatGPT. Пароль ChatGPT, access token и refresh
token не нужно отправлять в чат или вставлять в настройки приложения.
Порядок описан в [официальной инструкции](https://learn.chatgpt.com/docs/auth#login-on-headless-devices).

В этом сценарии выбран новый вход на VPS: копировать `auth.json` с Mac не нужно.
Если device flow недоступен, следует отдельно настроить официальный браузерный
вход с перенаправлением callback через SSH; не открывать callback всему интернету
и не извлекать токены из браузера.

Успешный `codex login status` подтверждает вход CLI, но не успешный ответ модели.
После входа нужны отдельные проверки: короткий настоящий запрос Luna, затем
сообщение в закрытом чате через HTTPS. При ошибке входа или исчерпании лимитов
приложение показывает ошибку, не объявляет мок ответом Codex и не переключается
на платный API.

## Изоляция CLI и смысл ответа модели

Адаптер допускает проверенную версию `codex-cli 0.163.0-alpha.11`. Для обновления
нужно повторить проверку реального каталога инструментов на соответствующей ОС.
Каждый вызов идёт в новую временную папку с `--ephemeral`, `--sandbox read-only`,
`--ignore-user-config`, `--ignore-rules`, строгой конфигурацией и отключённым
поиском пользовательских skills. Терминал, браузер, изображения, плагины, MCP,
подагенты и прочие встроенные инструменты отключены. Промпт получает историю
поездки и описания разрешённых инструментов приложения.

Модель возвращает JSON-конверт. Адаптер проверяет завершение CLI, формат ответа,
имена инструментов, уникальность идентификаторов вызовов и объект аргументов.
Фактический поиск и расчёты выполняет существующий реестр проекта. Нативный
вызов команды CLI считается ошибкой, а не инструментом поездки. При отмене,
ошибке или таймауте завершается группа процессов CLI; сырые сообщения CLI и
данные аккаунта в ответ браузеру не отправляются.

Используется только `gpt-6-luna` с `model_reasoning_effort=low`. Более медленная
модель и платный ускоренный service tier не подставляются. Точное время ответа
не гарантируется: оно зависит от сети, очереди и лимитов аккаунта. Ответ модели
буферизуется до проверки, поэтому этот режим не показывает её сырой поток токенов.

Авторизованный `/health` сообщает `llm_provider=codex_private`,
`codex_model=gpt-6-luna`, `codex_reasoning_effort=low` и
`codex_completed_calls`. Последнее — число успешно проверенных вызовов текущего
процесса; после перезапуска оно обнуляется. Счётчик не заменяет проверку
содержимого настоящего ответа.

## Что остаётся демонстрационным

Codex используется для разбора свободного текста и формулировки ответов.
Подключение модели не превращает сохранённые данные в текущие предложения:

- `TOOLS_MODE=real`, `FLIGHTS_MODE=demo`, `CACHE_MODE=replay`: используются
  ранее сохранённые ответы Aviasales из D4 и явно отмеченные дополнения
  «ДЕМО-МОК»; нового онлайн-поиска авиабилетов нет.
- `TRAINS_MODE=synthetic`: расписание и цены поездов синтетические.
- Цены отелей и трансферов расчётные; наличие услуги не подтверждено.
- Отзывы и профили D7 основаны на синтетических примерах. Подключение чата
  не подтверждает настоящий LLM-прогон извлечения D7.
- Оплата имитируется; билеты и отели у поставщиков не бронируются.

Заказы продолжают храниться в существующем постоянном томе
`na-maldivy-public_agent-state`, файл `/state/checkout.sqlite3`. Перед сменой
backend сделана отдельная согласованная резервная копия SQLite. Развёртывание
не должно удалять том или переносить заказы в пустую базу; после него нужно
повторно проверить доступность документов ранее оформленных демо-заказов.

Проверки кода: `backend/tests/test_personal_codex_access.py`,
`backend/tests/test_llm_codex_local.py` и
`frontend/integration/personal-codex.test.mjs`. Они используют подставные
процессы/ответы и проверяют границы приложения. Доказательство настоящего
серверного вызова хранится отдельно от таких тестов в отчёте, указанном выше.
