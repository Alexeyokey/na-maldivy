# D8: календарь и экономия от сдвига дат

`app.tools.price_calendar.price_calendar(query, search)` принимает D1-запрос и
асинхронный поиск D2. Для каждого календарного дня возвращает минимум цены
перелёта в одну сторону за всю группу, пометку синтетики или `null`, если данных
нет. Ноль не обозначает неизвестность. Календарь не является наличием билетов.

`suggest_date_shifts(selected, quote_trip)` сравнивает даты ±1–3 дня с исходной.
Каждая котировка должна включать перелёты туда-обратно с необходимым багажом,
полную цену всех ночей/комнат и остальные расходы. Адаптер возвращает `None`,
если хотя бы одна необходимая составляющая недоступна. Сравниваются один отель,
тот же состав группы, число ночей и тип источника (синтетика/реальные данные).
Положительная разница только в цене перелёта не считается экономией поездки.

Порог по умолчанию строго больше 5%; сравнение выполняется через `Decimal`.
Возвращаемые факты содержат суммы до/после, экономию в рублях и процентах,
разницу по перелётам/отелю/прочим расходам, дату и физический hotel_id.
Преобразование в R3 и SSE выполняется после O1. Модуль не меняет события чата.

## Адаптер D1 и проверка D2

PriceCalendarTool принимает общий PriceCalendarQuery и использует инъецированный
FlightTool. Публичный list[DayPrice] содержит только известные дни, потому что
цена DayPrice не nullable. Богатый PriceCalendar сохраняет каждый день с null для
отсутствующих предложений; пустой месяц не выдаётся за бесплатные перелёты.
Ошибка источника распространяется, не превращаясь в пустой успешный календарь.

`make d8-check` проверяет модуль и реальные результаты D2, `make d8-demo` выводит
месячный календарь для двух взрослых. Суммы — в одну сторону за группу, без багажа.
В provider mode источник/HTTP-клиент задаёт вызывающий код через FlightTool; этот
PR не делает новых запросов Aviasales и не подтверждает доступность билетов.

Экономия относится к явно сопоставленным компонентам TripQuote: перелёты туда-обратно
с обязательным багажом, все комнаты/ночи и явно переданные прочие расходы. Нулевой
other_total нельзя использовать вместо неизвестной обязательной доплаты. Перед
публикацией «полной цены поездки» вызывающий адаптер обязан получить остальные
обязательные расходы и проверить S5. Неполный вариант возвращает None.
Процент для отображения округлён до сотых; проверка строгого порога выполняется
точным целочисленным сравнением до округления. Сдвиг на один рубль выше 5% не теряется.

Модуль возвращает факт DateSaving для R3; отправка факта в чат/события интерфейса
остаётся общей интеграцией A2/R3. PR основан на D2, после его слияния базу нужно
перевести на main. Никакие архитектура агента или события O1 здесь не меняются.
