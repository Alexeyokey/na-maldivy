# Данные демо: что хранится в Git и что вычисляется

Проверено 29.10.2026 МСК в рабочем дереве подготовки на основе `ca76d20`.
Текущий набор содержит **247 файлов `data/`, 3 087 993 байт**,
включая обновлённую атрибуцию. Это размеры конкретного среза; последующие
правки документации могут изменить число байт без изменения самих данных.
Для работы подготовленных данных не нужны частные runtime-кэши, ключи
поставщиков или личный доступ владельца. Стандартный запуск использует
`LLM_PROVIDER=fake`: правила и шаблоны, а не настоящую языковую модель.

## Как получить данные и запустить проверку

Полный набор включён в `main` коммитом `62222c0` при слиянии подготовки
локального запуска. Его Git-дерево `data/` побайтово совпадает с исходным
`ca76d20` (`bea1c873fb98342a10adf43d18cfcb1ec76b1fe9`). В текущей подготовке
изменён только `data/ATTRIBUTION.md`: каталоги, фикстуры и снимки сохранены.
Специальная личная ветка для получения данных не требуется. Это утверждение
о данных; последующие изменения интерфейса проверяются и сливаются отдельно.

Для проверки решения достаточно стандартного запуска из [README](../README.md):

```bash
git clone https://github.com/ostrovok-hackathon-2026/na-maldivy.git
cd na-maldivy
cp .env.example .env
docker compose up --build
# открыть http://localhost:8080
```

Данные встроены в образ, таблицы SQLite создаются автоматически. Первой сборке
нужны публичные базовые образы и пакеты либо подготовленный Docker-кэш.
После запуска демонстрационные инструменты не обращаются к поставщикам.
Архив Docker-образов не хранится в Git; отдельный
[переносимый пакет](offline-package.md) — дополнительный способ запуска.

Названия и координаты OSM, дорожные измерения OSRM, справочные снимки климата/ЦБ
и сохранённые ответы Aviasales имеют отдельную provenance. Коммерческие условия
отелей, цены и расписания трансферов, модельные рейсы и поезда остаются синтетикой.
Данные не подтверждают наличие мест, цену покупки или условия реального отеля.
Происхождение и ограничения перечислены в [атрибуции](../data/ATTRIBUTION.md),
[описании снимка ЦБ](../data/CBR-ATTRIBUTION.md),
[источниках отелей](../data/hotels/sources.json),
[описании трансферов](../data/transfers/README.md) и
[описании снимков Aviasales](../data/demo/aviasales/README.md).
Происхождение ответа поставщика не подтверждает наличие мест или разрешение
на произвольное повторное распространение его данных.

Пять иллюстраций интерфейса находятся отдельно от `data/`, в
[`frontend/dist/assets/`](../frontend/dist/assets/README.md). Это оригинальные
статические SVG проекта, а не фотографии отелей. Они используют локальные
формы и градиенты без внешних ресурсов и шрифтов. API-интерфейс и отдельный
локальный прототип уже ссылаются на SVG; прежние JPG исключены из текущего дерева.

`TOOLS_MODE=stub` выбирает отдельный минимальный набор D1. Для общего каталога
60 отелей и источников D2–D8 нужен `TOOLS_MODE=real`; для смешанного офлайн-демо
рейсов дополнительно задаются `FLIGHTS_MODE=demo`, `TRAINS_MODE=synthetic`,
`CACHE_MODE=replay`. Код stub также отслеживается Git, его сведения не следует
смешивать с источниками общего каталога.

## Три направления и единые ID

AYT, DXB и MLE имеют по 20 отелей. Наборы `hotel_id` в исходном OSM-снимке,
каталоге D3, правилах, alias-значениях, S4, отзывах и профилях совпадают:
60 уникальных идентификаторов `osm:<type>/<id>`. Подмена одного физического
отеля другим для совместимости не выполняется.

Для сценария 18–25 ноября 2026, двое взрослых:

| Направление | Туда | Обратно |
|---|---|---|
| Анталья AYT | Сохранённая котировка Aviasales | Сохранённая котировка Aviasales |
| Дубай DXB | Явно помеченный детерминированный мок | Сохранённая котировка Aviasales |
| Мальдивы MLE | Сохранённая котировка Aviasales | Сохранённая котировка Aviasales |

47 HTTP-ответов не означают 47 подходящих рейсов: часть ответов содержит другой
аэропорт или дату. В частности, DWC не переименовывается в DXB.
Только `FLIGHTS_MODE=demo` дополняет отсутствующие данные помеченными моками.
Строгий `aviasales` не скрывает ошибки или отсутствие котировок синтетикой.
Для дат вне сохранённых ответов `demo` также может построить мок.

## Проверка целостности без изменения данных

Для разработчика с Python 3.12+ и `uv` доступны отдельные проверки. На первой
команде нужны публичные пакеты либо подготовленный кэш; последующие команды
не вызывают внешние API и не перезаписывают данные:

```bash
uv sync --project backend --locked
uv run --project backend --locked --offline python scripts/check_demo_cache.py
uv run --project backend --locked --offline python scripts/fetch_hotels.py --check
uv run --project backend --locked --offline python scripts/build_hotel_profiles.py --check
uv run --project backend --locked --offline python scripts/build_destinations.py --check
```

Повторены 29.10.2026 МСК в текущем рабочем дереве подготовки: 47 записей
Aviasales с проверкой manifest и SHA256, общий каталог по 20 отелей AYT/DXB/MLE,
60 D7-профилей и 48 направлений.
Все четыре проверки завершились успешно. Проверка Aviasales сообщила
`credentials_used=false`, `network_used=false`; D7 — `live_model_calls=0`.
Это проверка подготовленных данных, а не актуальных тарифов или качества LLM.

## Пересоздание данных разработчиком

Следующие команды используют сохранённые входы, работают без сети и
**перезаписывают** производные файлы. Для проверки судьёй они не нужны.
Историческое побайтовое воспроизведение описано ниже:

```bash
uv run --project backend --locked --offline python scripts/fetch_hotels.py
uv run --project backend --locked --offline python scripts/build_hotel_rules.py
uv run --project backend --locked --offline python scripts/build_hotel_profiles.py --generate-reviews
uv run --project backend --locked --offline python scripts/build_destinations.py
uv run --project backend --locked --offline python backend/scripts/build_transfers.py build
```

`fetch_hotels.py` вопреки историческому имени делает локальную проекцию общего
каталога. Настоящее обновление OSM/OSRM — отдельная сетевая команда
`backend/scripts/build_transfers.py fetch`; обновление климатических снимков —
`scripts/fetch_destination_climate.py`. Для воспроизведения демо они не нужны.
Синтетические JSON-формы Aviasales/Яндекса написаны вручную, их не следует
перезаписывать или выдавать за записанные ответы провайдера.

## Что намеренно отсутствует

- Ключи Aviasales/Яндекса/OpenAI, `.env`, пароли сайта, SSH-данные, авторизация Codex и TLS-ключи.
- Частные runtime-кэши `data/cache/aviasales/`, `data/cache/yandex/`, `.runtime/` и `artifacts/`.
- История личных чатов, реальные заказы, runtime SQLite и браузерные данные.
- Настоящий записанный ответ Яндекс Расписаний: в репозитории есть только синтетическая фикстура.
- Результаты настоящего LLM-извлечения D7: 60 опубликованных профилей получены воспроизводимым лексическим baseline, не LLM.
- Веса локальной модели, загруженные зависимости и собранные Docker-образы.

Публичные очищенные Aviasales-снимки специально перенесены в
`data/demo/aviasales/`, поэтому отсутствие частного runtime-кэша не мешает демо.

## Историческое независимое воспроизведение

Отдельный отчёт от 28.10.2026 относится к `37037e6`, а не к текущему дереву
всего приложения. Из `git archive 37037e6` извлечены только отслеживаемые файлы. Создано новое
окружение из lock-файла в offline-режиме с подготовленным кэшем пакетов.
Пустой HOME и очищенное окружение исключили доступ к ключам; подключения
socket и DNS были запрещены на уровне Python.

Прошли 10 проверок: D5, проекция D3, правила D3, D7, 47 Aviasales-снимков,
CLI D2/D4/D6/D8 и HTTP-сценарий всех трёх направлений до демо-оплаты,
ваучера и календаря. Все 5 генераторов воспроизвели исходные байты `data/`.
Настоящий LLM и внешний API при этом не вызывались; браузерный UI в этой
проверке не запускался.

С исправлениями аудита в том же изолированном окружении прошли **548 тестов**
данных и инструментов, включая загрузку повреждённой базы S4, целостность
manifest Aviasales и пять прогонов из исходного архива без Git.
