# Данные демо: что хранится в Git и что вычисляется

Текущий стандартный `FLIGHTS_MODE=demo` подключает все **48 направлений D5**:
**420 отелей, 10 080 синтетических отзывов, 420 профилей, 95 маршрутных
записей и 420 записей трансферов**. Исходные три направления AYT/DXB/MLE
сохранены отдельным слоем; расширение остальных 45 целей явно вымышленное.
Для работы подготовленных данных не нужны частные runtime-кэши, ключи
поставщиков или личный доступ владельца. Стандартный запуск использует
`LLM_PROVIDER=fake`: правила и шаблоны, а не настоящую языковую модель.

Размер **247 файлов `data/`, 3 087 993 байт** относится к историческому срезу
`c4f6b3c` от 29.10.2026 до расширения и не описывает нынешний набор.

## Покрытие и границы режимов

В режиме `demo` поддержаны перелёты из Москвы (аэропорт SVO) и Петербурга
по каталогу D5, отели, трансферы, D7/D8 и демо-оформление. Собственный маршрут
LED → LED не создаётся. Сохранённые рейсы по-прежнему берутся из исходных
47 очищенных ответов Aviasales; отсутствующие корректные данные дополняются
отдельной детерминированной моделью с меткой «ДЕМО-МОК». На новых направлениях
расписание и цена перелёта полностью модельные, а не ответы поставщика.

`FLIGHTS_MODE=synthetic` использует только исходную сеть шести записей
AYT/DXB/MLE, без новых отелей и трансферов. Строгий `aviasales` также не
подключает расширение и не заменяет отсутствующие котировки моками.
Сам D5 остаётся справочником 48 целей во всех режимах; справочная запись
не обещает полного подбора в отключённом режиме источников.

Для остальных 45 направлений сохранены 360 вымышленных отелей по 8 на цель,
360 записей трансферов с 1080 вариантами, 8640 синтетических отзывов и
360 профилей. Идентификаторы `demo:hotel/CMB-01` не являются OSM; имена и
координаты этих отелей также вымышлены. У каждого направления есть семейные,
pet-friendly, возвратные и круглосуточные варианты, а также ограничения
adults-only и невозвратные тарифы. Стабильное демонстрационное наличие одного
безопасного семейного варианта — правило фикстуры, а не наличие у поставщика.
Жёсткий бюджет, длительность перелёта или другие условия могут дать пустой
результат: генератор не изменяет их ради успешного ответа.

Расписания и тарифы строятся на дату запроса. Раздувать Git записями на каждый
день не требуется. Известная сумма за группу не является полной ценой поездки:
обратный трансфер, визы и прочие обязательные доплаты не оценены.

В исходном слое при аудите исправлены 12 корпусов и 12 профилей `adults_only`: теперь
семейные тексты не рекомендуют отдых с детьми вопреки синтетическим правилам.
Остальные 48 пар отзывов/профилей сохранены побайтово. Описание младенческих
тарифов маршрутной сети приведено к действующей модели `infant-v2`.
Поиск на месяц с ограничениями перелёта проверяет подходящие дни и обратное
плечо, а не останавливается на неподходящей дешёвой дате.

На Мальдивах база трансферов не подтверждает перевозку питомцев: остаются
`false`/`null`, а не вымышленные `true`. Отсутствующие/повреждённые ответы
поставщика не выдаются за свежие котировки. Все коммерческие условия — демо.

[Историческая матрица трёх направлений](../eval/reports/demo-data-coverage-2026-10-29/README.md).
Повторяемые read-only аудиты для разработчика:

```bash
uv run --project backend --locked --offline python scripts/check_demo_coverage.py \
  --data-dir data --output /tmp/demo-coverage.json
make expanded-demo-check
```

Первая команда проверяет исходные данные и базовую матрицу. Вторая —
расширенные данные и 1782 случая планировщика, ориентировочно 100 секунд.
Обе работают без сети и модели; их область — данные и планировщик, без чата,
браузера и оформления. Это не проверка настоящего API или качества LLM.

## Как получить данные и запустить проверку

Исходный набор трёх направлений включён в `main` коммитом `62222c0` при слиянии подготовки
локального запуска. Его Git-дерево `data/` побайтово совпадает с исходным
`ca76d20` (`bea1c873fb98342a10adf43d18cfcb1ec76b1fe9`). В срезе `c4f6b3c`
изменён только `data/ATTRIBUTION.md`: каталоги, фикстуры и снимки сохранены.
Эти утверждения относятся к исходному слою, а не к добавленным позже
`data/demo/*.generated.json` и новым отзывам/профилям.
Специальная личная ветка для получения данных не требуется. Это утверждение
о данных; последующие изменения интерфейса проверяются и сливаются отдельно.

Для проверки решения достаточно стандартного запуска из [README](../README.md):

```bash
git clone https://github.com/ostrovok-hackathon-2026/na-maldivy.git
cd na-maldivy
cp .env.example .env
docker compose up --build
# открыть http://localhost:8080
```

Данные встроены в образ, таблицы SQLite создаются автоматически. Первой сборке
нужны публичные базовые образы и пакеты либо подготовленный Docker-кэш.
После запуска демонстрационные инструменты не обращаются к поставщикам.
Архив Docker-образов не хранится в Git; отдельный
[переносимый пакет](offline-package.md) — дополнительный способ запуска.

## Проверка целостности без изменения данных

Для разработчика с Python 3.12+ и `uv` доступны отдельные проверки. На первой
команде нужны публичные пакеты либо подготовленный кэш; последующие команды
не вызывают внешние API и не перезаписывают данные:

```bash
uv sync --project backend --locked
uv run --project backend --locked --offline python scripts/check_demo_cache.py
uv run --project backend --locked --offline python scripts/fetch_hotels.py --check
uv run --project backend --locked --offline python scripts/build_hotel_profiles.py --check
uv run --project backend --locked --offline python scripts/build_destinations.py --check
uv run --project backend --locked --offline python scripts/build_demo_hotels.py --check
uv run --project backend --locked --offline python scripts/build_demo_transport.py --check
uv run --project backend --locked --offline python scripts/build_destination_names.py --check
```

Последние три команды проверяют воспроизводимость новых отелей/отзывов/профилей,
маршрутов/трансферов и общих имён D5 в backend/frontend. Они не перезаписывают
ни исходные, ни производные файлы. Все 420 отелей используют согласованные
ID в D3/S4/D7; у новых отелей код в ID совпадает с направлением.

Повторены 29.10.2026 МСК при подготовке среза `c4f6b3c`: 47 записей
Aviasales с проверкой manifest и SHA256, общий каталог по 20 отелей AYT/DXB/MLE,
60 D7-профилей и 48 направлений.
Все четыре исходные проверки завершились успешно. Проверка Aviasales сообщила
`credentials_used=false`, `network_used=false`; D7 — `live_model_calls=0`.
Это проверка подготовленных данных, а не актуальных тарифов или качества LLM.

## Пересоздание данных разработчиком

Следующие команды используют сохранённые входы, работают без сети и
**перезаписывают** производные файлы. Для проверки судьёй они не нужны.
Историческое побайтовое воспроизведение описано ниже:

```bash
uv run --project backend --locked --offline python scripts/fetch_hotels.py
uv run --project backend --locked --offline python scripts/build_hotel_rules.py
uv run --project backend --locked --offline python scripts/build_hotel_profiles.py --generate-reviews
uv run --project backend --locked --offline python scripts/build_destinations.py
uv run --project backend --locked --offline python backend/scripts/build_transfers.py build
uv run --project backend --locked --offline python scripts/build_demo_hotels.py
uv run --project backend --locked --offline python scripts/build_demo_transport.py
uv run --project backend --locked --offline python scripts/build_destination_names.py
```

Дополнения пересобираются после D5 и исходного слоя в порядке: отели →
транспорт → общие имена. Новые отзывы/профили пишутся только в `data/demo/`;
исходные 60 OSM-записей и их профили этими генераторами не меняются.

`fetch_hotels.py` вопреки историческому имени делает локальную проекцию общего
каталога. Настоящее обновление OSM/OSRM — отдельная сетевая команда
`backend/scripts/build_transfers.py fetch`; обновление климатических снимков —
`scripts/fetch_destination_climate.py`. Для воспроизведения демо они не нужны.
Синтетические JSON-формы Aviasales/Яндекса написаны вручную, их не следует
перезаписывать или выдавать за записанные ответы провайдера.

## Что намеренно отсутствует

- Ключи Aviasales/Яндекса/OpenAI, `.env`, пароли сайта, SSH-данные, авторизация Codex и TLS-ключи.
- Частные runtime-кэши `data/cache/aviasales/`, `data/cache/yandex/`, `.runtime/` и `artifacts/`.
- История личных чатов, реальные заказы, runtime SQLite и браузерные данные.
- Настоящий записанный ответ Яндекс Расписаний: в репозитории есть только синтетическая фикстура.
- Результаты настоящего LLM-извлечения D7: все 420 опубликованных профилей получены воспроизводимым лексическим baseline, не LLM.
- Веса локальной модели, загруженные зависимости и собранные Docker-образы.

Публичные очищенные Aviasales-снимки специально перенесены в
`data/demo/aviasales/`, поэтому отсутствие частного runtime-кэша не мешает демо.
